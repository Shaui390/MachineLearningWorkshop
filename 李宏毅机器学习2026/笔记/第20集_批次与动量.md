1. **为什么这集讲 batch**（[00:11]–[00:35]）：不是老师原本计划的内容 ——「因为**助教的程式里面有这一段**，所以我决定先告诉大家用 Batch 这个东西」。
2. **名词先立住**（[00:36]–[02:10]）：**batch（mini-batch）**= 每次 update 拿出来算 loss / gradient 的那 B 笔资料；**epoch** = 所有 batch 都看过一遍；**shuffle** = 每个 epoch 开始前**重新分一次** batch。
3. **两种极端，各自的好处**（[02:20]–[05:22]）：**full batch**（B = 全部 20 笔）→ 看完所有资料才能 update 一次，"**蓄力时间长**"但方向稳；**B = 1** → 每看一笔就 update 一次，"**技能冷却短**"但方向"曲曲折折"、"乱枪打鸟"。
4. ⭐ **第一个反直觉：平行运算**（[05:28]–[11:35]）：「你会觉得左边冷却时间长……**那只是你没有考虑平行运算而已**」→ 实测：batch size 1→1000，**算一次 gradient 的时间几乎一样**；batch 到 1 万 / 6 万才开始变慢（GPU 有极限）。于是 **一个 epoch 的总时间**大 batch 反而**更短**。
5. ⭐ **第二个反直觉：大 batch 连 training 都更差**（[11:59]–[13:43]）：实验一（MNIST / CIFAR-10）里 batch 越大，**validation 差、training 也差** → 同一个 model ⇒ **不是 model bias**；training 自己就差 ⇒ **不是 overfitting** ⇒ 是 **optimization 的问题**。
6. **机制解释**（[13:57]–[15:11]）：每个 batch 的 loss function 都**略有差异**（L¹、L²……）→ 在 L¹ 上卡住了，换 L² 不一定卡住 → **noisy 的 update 反而帮得上忙**。
7. ⭐ **第三个反直觉：小 batch 在 testing 上也更好**（[15:15]–[17:10]）：实验二（Keskar et al.）**先把大 batch 也 train 到跟小 batch 差不多的 training accuracy**，此时 testing 上小 batch 仍然赢 → ⭐ **这才是 overfitting**。
8. ⭐ **解释：平坦极小 vs 尖锐极小**（[17:13]–[20:10]）：把 training / testing 的 loss 差距画成"**往右平移一点**"→ 平原里的 minima 平移后几乎不变，峡谷里的 minima「一差就天差地别」→ 大 batch 倾向走进**尖锐**（坏）的 minima，小 batch 的噪声让它困不进窄峡谷。⚠️ [20:03]「**这只是一个解释，那也不是每个人都相信这个解释**」。
9. **收束成一张对比 + 一个身份**（[20:16]–[21:33]）：两边各有擅长 → **batch size 是又一个需要调的 hyperparameter**。
10. **鱼与熊掌**（[21:33]–[22:38]）：大 batch + 特别的方法可以兼得 → 76 分钟 train BERT、15 分钟 train ResNet-50、1 小时 train ImageNet；代价是"需要有一些特别的方法来解决大 batch size 可能带来的劣势"。
11. **动量的物理直觉**（[22:38]–[23:57]）：error surface = 斜坡、参数 = 球；**有惯性** → 走到 saddle point / local minima **不一定停住**，动量够大能翻过小坡继续走。
12. **动量的更新方式**（[24:40]–[27:43]）：**不是只往 gradient 的反方向走**，而是「**gradient 的反方向**」与「**前一步移动的方向**」**两者相加的折中**。
13. ⭐ **另一种读法**（[27:43]–[29:08]）：把 m 展开 → **update 方向考虑的是"过去所有 gradient 的总和"**，不只现在的 gradient。
14. **一个更简单的例子**（[29:08]–[30:38]）：走到 local minima、gradient = 0，一般 GD 走不动了，但**前一步的方向还在** → 继续往右；甚至 **gradient 说往左，只要前一步的影响更大，还是可能往右**、翻过小丘到更好的 local minima。

## 二、核心概念

### 1. 名词先立住：batch / epoch / shuffle

- **batch（mini batch）**：每次 update 参数时拿出来算 loss / gradient 的 **B 笔资料**。（老师 [00:50]「有的是叫做 Mini Batch，那我这边叫做 Batch，其实指的是一样的东西」。）
- **update 一次** = 拿一个 batch 算 loss → 算 gradient → 更新参数（**不是**拿全部资料）。
- **epoch**：**所有 batch 都看过一遍**（[01:24]「所有的 Batch 看过一遍，叫做 Epoch」）。
- ⭐ **shuffle**（[01:38]–[02:04]）：**每个 epoch 开始之前重新分一次 batch**，所以"哪些资料在同一个 batch 里面，每一个 Epoch 都不一样"。助教的程式里就有这一段。

> ⚠️ **epoch ≠ update**（P3 就踩过的坑，这里再确认一次）：资料 6 万笔、B = 1 → **一个 epoch = 6 万次 update**；B = 1000 → **一个 epoch 只有 60 次 update**。

### 2. 两种极端的对比（老师用游戏比喻包装）

| | **Full Batch**（B = 全部资料） | **Batch size = 1** |
|---|---|---|
| 什么时候 update | 全部资料看完才 update **一次** | **每看一笔**资料就 update 一次 |
| 20 笔资料的一个 epoch | **1 次** update | **20 次** update |
| 方向 | **稳**（[04:56]「它这一步走的是稳的」） | **noisy**、曲曲折折（"乱枪打鸟"） |
| 老师的比喻 | **蓄力时间长**、威力大 | **技能冷却时间短**、但比较不准 |

⚠️ 比喻只是包装，**下一节就把"时间"这条给拆了** —— 所以比喻本身**不用记**（用户 2026-09-18 明确表示不记比喻，记原理即可）。

> 🔗 **顺带一句**：[14:14] 老师在讲 full batch 卡住时说「如果你**不特别去看 Hessian** 的话，那你用 gradient descent 的方法就没有办法再更新你的参数了」—— **本集只掠过这一句**，与 P19 的 🔶 待补段无关（P19 已说明实作上几乎没人算 Hessian）。

### 3. ⭐ 第一个反直觉：平行运算把"大 batch 慢"这个劣势消掉了

![[P20_01_一个epoch的时间_小batch更慢.png]]

**实测**（MNIST，V100，[06:07]–[08:25]）：batch size = 1 / 10 / 100 / 1000 时，**算一次 gradient 的时间几乎一样**（[06:55]「所需要耗费的时间几乎是一样的」）。为什么？

> [07:13]–[07:29]「因为在实际做运算的时候，**我们有 GPU，你可以做平行运算**……所以这 1000 笔资料是**平行处理**的，1000 笔资料所花的时间**并不是一笔资料的 1000 倍**。」

⚠️ **但平行能力有极限**（[07:30]–[08:25]）：batch 拉到 **1 万、6 万**时，算完一个 batch 的时间**确实会随 batch size 增加而增长**（V100 塞 6 万笔约 **10 秒**；老师放的旧投影片里，早年（2015/2017）的卡跑同一个 batch 要"好几分钟"）。

**⭐ 关键一步：把"一次 update 的时间"换成"一个 epoch 的时间"**（[09:02]–[10:57]）：

| 资料 6 万笔 | 一个 epoch 要 update 几次 | 单次 update 时间 | **一个 epoch 总时间** |
|---|---|---|---|
| **batch size = 1** | **60000 次** | 很短（≈ 1 笔） | **很长**（≈ 350+ 秒） |
| **batch size = 1000** | **60 次** | 略长一点点（≈ 10 秒） | **短得多** |

⇒ 投影片标题就是结论：**"Smaller batch requires longer time for one epoch (longer time for seeing all data once)"**；两张图的趋势**正好相反**（左图 = 单次时间随 batch 变大而升；右图 = 一个 epoch 的总时间随 batch 变大而降）。
⇒ [10:59]–[11:34]「直接用**技能时间冷却的长短**，并不是一个精确的描述……**大的 batch 并没有比较吃亏，甚至还占到优势了**」。

### 4. ⭐ 第二个反直觉：大 batch 连 training 都更差（实验一 = optimization 问题）

![[P20_02_实验一_准确率vs批次大小_MNIST与CIFAR10.png]]

**做法**：同一个 model，只改 batch size（1 → 60000），看 accuracy。

**看到的现象**（两个 dataset 都一样）：

| | batch 小（1–1000） | batch 大（10000–60000） |
|---|---|---|
| **validation acc** | 高 | **差** |
| **train acc** | 高 | **也差**（不是只有 validation 掉） |

**⭐ 三步判定（本集最重要的推理，比结论本身重要）**：

```
validation 差、training 也差
   → 用的是同一个 model ⇒ 能表示的 function 一模一样 ⇒ 排除 model bias
   → training 自己就差 ⇒ 不满足 overfitting 的定义 ⇒ 排除 overfitting
   ⇒ 只剩一格：这是 optimization 的问题
```

> 老师说得很直接：[12:52]「但这个是 overfitting 吗？**这个不是 overfitting**」；[13:26]「同样的 model……所以这个不是 model bias 的问题，**这个是 optimization 的问题**」。

**机制：每个 batch 的 loss function 都不一样**（[13:57]–[15:11]）

![[P20_03_机制_noisy_update为何有帮助.png]]

- full batch 只有**一个** loss function → 走到 local minima / saddle point，gradient = 0 → **就停住了**。
- 小 batch 每次挑出来的资料不同 → 每次 update 用的 **loss function 都略有差异**（L¹、L²…）：
  > [14:45]–[15:03]「假设你用 L¹ 算 gradient 的时候，发现 gradient 是 0，**卡住了**；但 L² 它的 function 跟 L¹ 又不一样……**L¹ 卡住了，没关系，换下一个 batch 来**，你还是有办法 train 你的 model。」
- ⇒ **"noisy" 在这里是优点**（投影片："**"Noisy" update is better for training**"）。

### 5. ⭐ 第三个反直觉：小 batch 在 testing 上也更好（实验二 = overfitting）

![[P20_04_实验二_Keskar_训练与测试准确率表.png]]

**出处**：Keskar et al.《On Large-Batch Training for Deep Learning: **Generalization Gap and Sharp Minima**》（[15:51]）；**6 个 network**（2 个全连接 + 4 个卷积）× 4 个 dataset（MNIST / TIMIT / CIFAR-10 / CIFAR-100）→ 说明**这个现象很普遍**。

**设定**：**SB（small batch）= 256**；**LB（large batch）= 0.1 × dataset**（6 万笔资料 → 6000 一笔）。

**⭐ 这一步是实验二与实验一的分水岭**：实验一里大 batch 的 training 本来就差，"测试差"可以赖到 training 头上；实验二**特意把 LB 也 train 到跟 SB 差不多**（表里 Training Accuracy 两列都在 99% 上下）——**在 training 一样好的前提下**，testing 上 **SB 仍然全面赢 LB**（6 个 network 全赢）。

⇒ [17:04]–[17:10]「training 的时候都很好，testing 的时候（大 batch）差，那代表什么？**代表 overfitting**。」

**机制：平坦极小（Flat Minima）vs 尖锐极小（Sharp Minima）**

![[P20_05_平坦极小vs尖锐极小_好与坏minima.png]]

1. loss 面上有**很多个** local minima，loss 都趋近于 0 —— 但分**好 minima** 与 **坏 minima**：**在宽的平原 / 盆地里的是好的，在窄峡谷里的是坏的**（[17:46]–[17:59]）。
2. **关键假设**：**training 的 loss 与 testing 的 loss 之间有差距**（[18:09]–[18:25]：可能分布本来就不同，也可能只是抽样到的资料不同）→ 老师把它画成「**把 training 的 loss function 往右平移一点**」。
3. 于是：**平原里的 minima** 平移之后 loss 只差一点点；**峡谷里的 minima**「**一差就天差地别**」——training loss 很低，testing loss 却很大（[18:36]–[19:07]）。
4. 为什么小 batch 会走到平原？[19:22]–[19:53]：小 batch 每次 update 方向都带随机性，「**一个很小的峡谷没有办法困住小的 batch**……如果有一个非常宽的盆地，它才会停下来」。

> ⚠️ [20:03]–[20:16]「**但这只是一个解释，那也不是每个人都相信这个解释**，那这个其实还是一个**尚待研究**的问题。」—— **笔记里必须跟着这句一起记**，别把它当成定论。

### 6. 收束：batch size 是一个超参数 + "鱼与熊掌"

**对比总表**（[20:16]–[21:33]）：

| | 小 batch | 大 batch |
|---|---|---|
| 单次 update 时间 | 差不多（有 GPU 时） | 差不多（batch 到 1 万以上才变慢） |
| **一个 epoch 的时间** | **长** | **短** ✅ |
| update 方向 | noisy | 稳定 |
| **optimization（training）** | **好** ✅（noisy 帮它跳出卡住的点） | 较差 |
| **testing** | **好** ✅（不易困在尖锐极小） | 较差 |

⇒ [21:20]「所以 **batch size 变成另外一个 hyperparameter**，这个 hyperparameter 是需要去调它的。」

**能不能兼得？**（[21:33]–[22:38]）

![[P20_06_鱼与熊掌_大batch训练的论文列表.png]]

可以 —— 用**超大 batch + 特别的方法**（老师只给 reference，不细讲）：

| 论文 | 成果 |
|---|---|
| Large Batch Optimization for Deep Learning（LAMB） | **76 分钟** train BERT |
| Extremely Large Minibatch SGD | **15 分钟** train ResNet-50 on ImageNet |
| Stochastic Weight Averaging in Parallel | 大 batch 也能泛化好 |
| Large Batch Training of Convolutional Networks（LARS） | — |
| Accurate, large minibatch SGD | **1 小时** train ImageNet |

⚠️ **字幕订正**：原始字幕把 "Training imagenet in **1 hour**" 听成「**1 分钟** train imagenet」（见投影片 `P20_06` 原文）。

### 7. 动量（Momentum）

**物理直觉**（[22:38]–[23:57]）：把 **error surface 当成真正的斜坡**，参数当成**一颗球**。

> 一般的 gradient descent 走到 local minima / saddle point **就停住了**；但在物理世界里，球从高处滚下来**有惯性** ——「就算滚到 saddle point，**因为惯性，它还是会继续往右走**……如果动量够大的话，它还是会继续往右走，甚至**翻过这个小坡**然后继续往右走」。

**复习 vanilla gradient descent**（[23:57]–[24:40]）：`θ⁰ → 算 g⁰ → 往 gradient 反方向 update → θ¹ → 算 g¹ → …`。

**⭐ 加上动量之后**（[24:40]–[27:43]）

![[P20_07_动量_移动量等于上一步移动减当前梯度.png]]

投影片的两句话就是全部：

> 蓝框：**Movement: movement of last step minus gradient at present**
> 绿框：**Movement not just based on gradient, but previous movement**

写成式子（老师的记法）：

```
m⁰ = 0
m¹ = λ·m⁰ − η·g⁰        θ¹ = θ⁰ + m¹
m² = λ·m¹ − η·g¹        θ² = θ¹ + m²
⋮
mᵗ⁺¹ = λ·mᵗ − η·gᵗ       θᵗ⁺¹ = θᵗ + mᵗ⁺¹
```

- **m = movement（移动量）**：这一步**往哪走、走多远**（图上的蓝色实线箭头）。
- **λ = 前一步移动量的权重**；**η = learning rate**。**两个都要调**（[28:17]「λ 就是另外一个参数，就跟 learning rate 一样是要调的」）。
- **几何读法**：每个点上是「**前一步的移动方向**（蓝色虚线）」与「**当前 gradient 的反方向**（红色）」**两个向量相加**，走**折中方向**（[26:47]「就把两者相加起来，走两者的折中」）。
- ⚠️ **第一步一点都不特别**：因为 m⁰ = 0，[25:56]–[26:00]「所以 update 的方向跟原来的 gradient descent 是一样的，**这没有什么有趣的地方**」→ **从第二步开始**才有差别（用户抓到的"从第二轮开始"就是这条）。

**⭐ 第二种读法：过去所有 gradient 的加权和**（[27:43]–[29:08]）

![[P20_08_动量展开_过去所有梯度的加权和.png]]

把 m 一路代回去：

```
m⁰ = 0
m¹ = −η·g⁰
m² = −λ·η·g⁰ − η·g¹
m³ = −λ²·η·g⁰ − λ·η·g¹ − η·g²
⋮
```

⇒ 投影片原句：**`mⁱ` is the weighted sum of all the previous gradient: `g⁰, g¹, …, gⁱ⁻¹`**。
⇒ [28:57]–[29:08]「**当加上 momentum 的时候，我们 update 的方向不是只考虑现在的 gradient，而是考虑过去所有 gradient 的总和**。」
⇒ ⭐ **越久以前的 gradient 权重越小**（乘了越多层 λ；λ < 1 时是衰减）。

**一个更简单的例子**（[29:08]–[30:38]）：从某个点开始往右 update → 走到 gradient 变很小的地方，但**前一步还在往右**，两者相加继续往右 → **走到 local minima，gradient = 0，一般 GD 走不动了，但 momentum 还有前一步的方向**（[30:12]「gradient 就算是零，你还有前一步的方向」）→ 继续往右；甚至「**gradient 告诉你应该要往左走了，但是假设你前一步的影响力比 gradient 要大的话，你还是有可能继续往右走**，甚至翻过一个小丘，搞不好就可以走到更好的 local minima」。

## 三、公式与推导要点

本集**没有需要线性代数的推导**（✅ 不用标 🔶 待补）。要带走的只有三件：

1. **batch 的两个时间**（别混）：
   - 一次 update 的时间 ≈ **不随 batch 大小变化**（有 GPU 时，1→1000 几乎相同）
   - 一个 epoch 的时间 = **update 次数 × 单次时间** → **大 batch 更短**
2. **动量的递推式**：`mᵗ⁺¹ = λ·mᵗ − η·gᵗ`，`θᵗ⁺¹ = θᵗ + mᵗ⁺¹`，`m⁰ = 0`。
3. **动量的展开式**（第二读法的来源）：`mᵗ⁺¹ = −η·Σ_{i=0}^{t} λ^(t−i)·gⁱ` —— 也就是"**过去所有 gradient 的加权和，越久权重越小**"。

## 四、我的理解（用户原话 + 检查结果）

### 4.1 用户费曼复述（原话照录，仅英文词两侧补了阅读空格）

> 第一部分老师先提出为什么要将数据分成 batch 一批批训练的疑问，然后展示了小 batch 和大 batch 的区别：当大 batch 数量在一定程度的时候，单个大的 batch 能够通过矩阵平行运算达到跟单个小 batch 近似的训练速度（所以大的 batch 一轮更新的速度更快）；小 batch 在训练上更容易受到噪点的影响，而大 batch 训练的过程更稳定；小 batch 优化的结果会优于大 batch（老师解释有人觉得小 batch 更容易将 loss 从峡谷中带出来，走到较为平缓的盆地，但是这是有待研究的假说）
>
> 第二部分是动量的内容，动量就是让模型从第二轮梯度下降开始用上一轮梯度的反方向 * lambda + 这一轮的梯度的反方向乘上学习率，来模拟物理世界中小球从凹凸不平的斜坡上下落的过程，这样能让小球更容易滚出 critical point

### 4.3 纠正一：动量式里 λ 乘的是 **m（移动量）**，不是"上一轮梯度的反方向"

|        | 正确                             | 用户说法                           |
| ------ | ------------------------------ | ------------------------------ |
| 式子     | `m² = λ·m¹ − η·g¹`             | `λ ×(上一轮梯度反方向) + η×(这一轮梯度反方向)` |
| λ 乘的对象 | **m¹ = 上一步的移动量**（已经含 η 与更早的 g） | 上一步的**梯度**反方向                  |

- **两者只在第一步凑巧相等**：因为 m¹ = −η·g⁰，所以"λ × m¹"与"λ × (−g⁰)"差了一个 η，数值上不等；更关键的是**第二步起 m¹ 里已经混进了 g⁰ 的历史**。
- ⇒ 说成"上一轮梯度的反方向"，**正好把动量最核心的"累积历史"丢掉了**（也就是 4.5 里 B9 没答出来的那个第二读法）。
- ⚠️ 另外**漏了 λ 本身也是要调的超参数**（[28:17]）。

## 五、易错点与纠正

1. ❌ **「大 batch 一次 update 更快」是错的** —— 单次 update 时间**几乎一样**；**快的是"一个 epoch 的总时间"**。⚠️ 别把"时间"当成一个笼统的量，**先问清是"一次 update"还是"一个 epoch"**。
2. ❌ **本集是"两个实验"，不是一个** —— 合成一个就会把**性质判反**（见下方对照表）。
3. ⚠️ **"1→1000 几乎一样"不等于"完全一样"** —— 是"几乎"；batch 超过某个量级（1 万 / 6 万）后**确实**会变慢（GPU 平行有极限）。
4. ⚠️ **判断 overfitting 需要前提** —— 必须先让**两边的 training 表现可比**；training 自己就差的情况下，只能说 **optimization 有问题**。
5. ⚠️ **λ 乘的是 m（movement）**，不是"上一轮的梯度反方向"；**λ 与 η 两个都要调**。
6. ⚠️ **动量的第一步和普通 GD 完全一样**（m⁰ = 0）——"从第二步开始才不一样"，所以别拿第一步的例子证明动量有效。
7. ⚠️ **"这只是个解释"** —— 大 batch 为什么会走到尖锐极小，老师自己说是**尚待研究**、**不是每个人都相信**（[20:03]）。笔记里**必须带着这句**。
8. ⚠️ **noise 在这集是"优点"** —— 与"噪声有害"的常识相反；但要注意语境：它帮的是 **optimization 与 testing**，不是"随便加噪声都好"。
9. 🧩 **epoch ≠ update** —— 一个 epoch 的 update 次数 = 资料数 ÷ batch size（6 万笔 / B=1000 = **60 次**）。
10. 📝 **两处字幕转写坑**（原始字幕打错，别照抄）：
    - [16:56] / [17:02] 把「**大** batch 在 testing 上比较差」听成「**小** batch 比较差」——与 [15:46] 和论文结论都矛盾，按"大 batch 差"写。
    - [22:11]「1 分钟 train imagenet」→ 投影片原文是 "**1 hour**"（1 小时）。

**两个实验的对照（最容易记混，单独留一张表）**：

| | **实验一** | **实验二** |
|---|---|---|
| 出处 | 老师自制（MNIST / CIFAR-10） | Keskar et al. `P20_04` |
| 设定 | 单纯改 batch size | **把 LB 也 train 到跟 SB 差不多**，再比 testing |
| 现象 | training 与 validation **一起变差** | training 一样好，**testing 上 SB 全面赢** |
| 性质 | **optimization 问题**（**不是** overfitting、**不是** model bias） | **overfitting** |
| 机制 | 每个 batch 的 loss 不同（L¹/L²）→ 卡住也能被下一批救出来 | 平坦极小（好）vs 尖锐极小（坏）+ training/testing loss 有差距 |
