## §1 本集讲了什么

### 1.1 一句话

**把"输入特征要标准化"这件事从第一层一路推广到中间层，就得到了 Batch Normalization：每一层算完线性输出 z，就拿"同一个 batch 里、同一个 dimension"的 μ/σ 把它拉回均值 0、方差 1；为了不把路堵死，再让它乘 γ 加 β（这两个是学出来的参数）。** 上线时没有 batch 可算，就用训练期间累积的移动平均 μ̄/σ̄ 顶上。最后半集讨论**"它为什么有用"**：原论文的 internal covariate shift 解释**被打脸**，现在比较站得住的说法是**它把 error surface 变得比较不崎岖** —— 而且这个效果**很可能是意外收获**。

⭐ 一个贯穿全集的角度：**标准化 = 把"难做的 error surface"直接改掉**，而不是像 P21 那样换一个更聪明的更新方式绕开它 [01:14]–[01:35]、[02:30]–[02:37]「直接把难做的 error surface 把它改掉，看能不能够改得好做一点」。

## §2 为什么需要标准化：烂的 error surface 是从哪来的

### 2.1 开场：为什么这一集现在才讲（[00:00]–[01:08]）

[00:14]–[00:41]：

> 「因为上课的内容想要**配合作业**的关系，所以我们会**先把作业需要的**……先讲一讲……就讲一些 training 的 tips，所以这样可能**有点散乱**了，就 **training 的 tips 散布在课程的各个地方**。」
> 「但 training 的 tips 这种东西，如果真的想讲的话是**永远都讲不完的**，这个 tips 实在是太多了。」

讲 BN 的时机 [00:46]–[01:05]：

> 「这个时候讲 Batch Normalization 是**最合适的**，因为 Batch Normalization 你在**作业3**是用得上的，而且**作业3助教的程式里面其实就有 Batch Normalization**，在做 CNN 的时候……今天做影像处理的时候，Batch Normalization 往往可以带来蛮大的帮助。」

⭐ **这一段的实用价值**：它解释了本笔记库 早就踩过的一个坑 —— **作业 01 里 `StandardScaler` / `nn.BatchNorm1d` "没学就用"不是失误，是课程既定顺序**（老师本人在 [09:04] 还补了一句「其实在**助教的 code 里面，我们都有对 feature 做 normalization**」）。

### 2.2 回顾：为什么"碗形"也不见得好走（[01:10]–[02:37]）

先把 P21 的结论搬过来 [01:45]–[02:18]：

> 「不要小看 Optimization 这个问题，有时候就算你的 error surface 是 **convex** 的，也就是它就是一个**碗的形状**，都不见得很好 train。那我们举的例子就是假设你的两个参数，他们对 Loss 的**斜率差别非常大**：在 `W1` 这个方向上面你的斜率变化很小，在 `W2` 这个方向上面斜率变化很大。你今天如果是**固定的 Learning Rate**，你可能很难得到好的结果。」

⇒ 以前的解法是"**换一个更聪明的走法**"（Adaptive LR、Adagrad 等等）。本集换方向：**把路修平**。

### 2.3 ⭐ 崎岖是从哪来的：`X` 的尺度 × `W` 的变化（[02:43]–[05:43]）

老师先问 [02:41]–[02:53]：「有这种状况……到底**是从什么地方来的**？」然后用一个**没有 activation function 的线性 model** 回答（[02:56]–[03:23]）：

```
x1 --×w1--┐
          ├─ 相加 ─→ y ─→ e = ŷ − y ─→ L = Σ e
x2 --×w2--┤
      b --┘          （L 是把所有 training data 的 e 加起来）
```

推导链（**注意：老师的斜率是两个"影响大小"连乘出来的**）[03:33]–[04:40]：

> 「`W1` 是透过 `W1` 改变的时候，你就改变了 `Y`；`Y` 改变的时候你就改变了 `E`；然后接下来就改变了 `L`。」
> 「什么时候 `W1` 这边的变化、它在 error surface 上的**斜率会很小**呢？**一个可能性是当你的 input 很小的时候**……假设 `X1` 的值都很小，那因为 `X1` 是直接乘上 `W1`，如果 `X1` 的值都很小，`W1` 有一个变化的时候，它对 `Y` 的影响也是小的，对 `E` 的影响也是小的，**它对 `L` 的影响就会是小的**。」

反方向（`X2` 很大）[04:53]–[05:22]：

> 「当你的 `W2` 有一个小小的变化的时候，虽然 `W2` 这个变化可能很小，但是**因为它乘上来 `X2`，`X2` 的值很大**，那 `Y` 的变化就会很大……那就会导致我们在 `W` 这个方向上做变化的时候，我们把 `W` 改变一点点，那我们的 error surface 就会有**很大的变化**。」

**结论** [05:25]–[05:41]：

> 「当我们 input 的 feature **每一个 dimension 的值，它的 scale 差距很大的时候**，我们就可能产生像这样子的 error surface —— 不同方向、它的斜率非常不同。」

![P48_01_ChangingLandscape_烂errorSurface从哪来_p3](P48_01_ChangingLandscape_烂errorSurface从哪来_p3.webp)

> 图注（投影片 **p3**，标题 `Changing Landscape`）：**上半两张图是"对比"** —— 左边蓝线是**崎岖**的等高线（`W1` 方向标 `smooth`、`W2` 方向标 `steep`，红色折线在里面来回震荡走得很痛苦）；右边绿线是**标准化之后**的同心圆，红色折线**直直朝中心去**。
> **下半是这条结论的推导**：`x1`（small）乘 `w1`、`x2`（large）乘 `w2`，两条路都汇到「`+`」再得到 `y`；一旦改变 `w1` ⇒ `+Δy` ⇒ `+Δe` ⇒ **`+ΔL`**（三个红字全标 **large**）。右下角还画了一个红框「**same range**」，把 `1, 2, ……`（small）和 `100, 200, ……`（large）括在一起 —— 那就是下一节要做的事。
> ⚠️ **本集只回答"崎岖从哪来"，没回答"崎岖为什么难训"** —— 后者是 P21 的账（[01:45]–[02:18] 只是把它当已知结论引用）。

## §3 标准化怎么做：feature normalization 与 standardization

### 3.1 命名先立住：统称 vs 具体做法（[05:43]–[06:29]）

[05:43]–[06:03] 先给目标：

> 「我们有没有可能给不同的 dimension feature 里面不同的 dimension，让它有**同样的数值的范围**？如果我们可以给不同的 dimension 同样的数值范围的话，那我们可能就可以制造比较好的 error surface，让 training 变得比较容易一点。」

[06:13]–[06:29] ⭐ **两个层次的名字**（这一段很容易记混）：

> 「其实有**很多不同的方法**，那这些不同的方法往往就**合起来统称为 feature normalization**。那我以下所讲的方法**只是 feature normalization 的一种可能性**，它并不是 feature normalization 的全部。」

⇒ 所以：**`feature normalization` 是统称，本集讲的是其中一种。**

### 3.2 做法：同一个 dimension、跨资料算 `m` 和 `σ`（[06:31]–[07:58]）

输入是一堆 feature vector `x¹ … x^R`（**上标 = 第几笔资料**），每笔里面有 `x₁ʲ, x₂ʲ, …`（**下标 = 第几个 dimension**）[06:44]–[06:53]。

1. **取同一个 dimension、不同笔资料的数值** [06:54]–[07:04]：「把**同一个 dimension、不同笔资料、不同 feature vector**，同一个 dimension 里面的数值，把它取出来」；
2. 算这个 dimension 的**平均值 `mᵢ`**、**标准差 `σᵢ`** [07:06]–[07:21]；
3. 逐个数做 [07:32]–[07:49]：

$$\tilde{x}^j_i=\frac{x^j_i-m_i}{\sigma_i}$$

⭐ **这一招有正式名字** [07:24]–[07:31]：

> 「那这种 normalization 呢**其实叫做标准化，也叫 standardization**，不过我们这边呢就等一下就**都统称 normalization** 就好了。」
> （⇒ 日常口语里"归一化 / 标准化 / normalization"经常混用，**在这个 笔记库 里按老师的口径统一叫 normalization**。）

### 3.3 好处：均值 0、方差 1 ⇒ 走得更顺（[08:02]–[08:58]）

[08:05]–[08:20]：

> 「做完 normalize 以后，这个 dimension 上面的数值就会**平均是 0**，然后它的 **variance 就会是 1**……所以这一排数值它的分布就都会在 **0 上下**。」

对每个 dimension 都做一遍 ⇒ [08:31]–[08:55]：

> 「所有 feature 不同 dimension 的数值都在 0 上下，那你可能就可以制造一个**比较好的 error surface**……它可以让你在做 gradient descent 的时候，你的 gradient descent 它的**收敛更快一点**。」

⚠️ 老师的用词是「**往往**对你的 training 有帮助」（[08:41]）—— 不是"一定"。

## §4 中间层也要标准化（[09:19]–[11:34]）

### 4.1 关键一句："对 `W2` 来说，`a`/`z` 也是 input"（[09:19]–[10:27]）

[09:15]–[09:35] 先走一遍前向：`x̃ → W1 → z → activation → a → 下一层`。

然后 [09:38]–[10:05] 是本集的**枢纽**：

> 「对 `W2` 来说，这边的 `a`、这边的 `z`，**其实也是另外一种 input**。虽然它已经 normalized，但是**通过 `W1` 以后它就没有做 normalized**。如果 `x̃` 通过 `W1` 得到 `z1`，而 `z1` 的**不同的 dimension 间它的数值的分布仍然有很大的差异**的话，那我们要 train `W2` 第二层的参数，**会不会也有困难呢**？」

⇒ 结论 [10:13]–[10:27]：「所以这样想起来，我们也应该要对这边的 `a` 或对这边的 `z` 做 feature normalization。**对 `W2` 来说，这边的 `a` 或这边的 `z` 其实也是一种 feature。**」

⭐ **这就是"标准化不能只做在输入层"的全部理由** —— 第 2 节那套推导（`X` 尺度差 ⇒ 斜率差）**对每一层都成立**，所以每一层都要治。

### 4.2 Q&A：放 activation 之前还是之后？（[10:29]–[11:34]）

这是**每次讲 BN 都会被问的问题**，老师的回答分两半：

1. **实作上差异不大** [10:41]–[10:54]：
   > 「在实作上这两件事情**其实差异不大**，你可以自己在座位里面试试看……所以你对 `z` 做 feature normalization，或对 `a` 做 feature normalization，**其实都可以**。」
2. **但选 sigmoid 时可能推荐对 `z`** [10:55]–[11:22]：
   > 「因为 sigmoid 是一个 **S 的形状**，它在**零附近斜率比较大**。所以如果你对 `z` 做 feature normalization，把所有的值都挪到**零附近**，你到时候**算 gradient 的时候，算出来值会比较大**。」
   （⚠️ 注意因果方向：**"挪到 0 附近 ⇒ 梯度大"** 才是结论；"S 形、两头平中间斜"只是前提。）

[11:24]–[11:31] 收尾：

> 「总之 in general 而言，这个 normalization 要放在 activation function 之前或之后**都是可以的**，在实作上可能没有太大的差别。」

⇒ **本集后续统一对 `z` 做**（[11:36]「我们这边就是对 `z` 做一下 feature normalization」）。

![P48_02_ConsideringDeepLearning_中间层也需标准化_p5](P48_02_ConsideringDeepLearning_中间层也需标准化_p5.webp)

> 图注（投影片 **p5**，标题 `Considering Deep Learning`）：这张图就是 §4.1 的论证。**竖着看三行**——最左是三个 `x̃¹ x̃² x̃³`（黑框，底下标 `Feature Normalization`：**输入已经标准化过了**），各自过一次蓝的 `W¹` 得到 `z¹ z² z³`，再各自过 `Sigmoid` 得到 `a¹ a² a³`，再往右进橙色的 `W²`（虚线画到 `……`）。
> **两个标注是重点**：① 从 `z¹` 那里引出的虚线写着 **`Different dims have different ranges.`**；② 从 `z` 这一列往下画的大黑箭头写着 **`Also need normalization`**，右侧橙色 `W²` 那里再引一条虚线写着 **`Also difficult to optimize`**。
> ⚠️ 图里最下面那个**红点**（在 `z²` 和 `Sigmoid` 之间）是老师讲 **§4.2** 时点的位置 —— **"normalization 要放 activation 之前还是之后"就发生在那里**。

### 4.3 对 `z` 做标准化的细节：`μ`、`σ` 都是向量（[11:36]–[13:40]）

把 `z` 当成新的 feature，步骤跟 §3.2 一模一样，只是**逐个数要按 dimension 分别做**：

$$\mu_i=\text{average of }\{z^1_i,\dots,z^n_i\},\qquad \sigma_i=\sqrt{\text{average of }\{(z^j_i-\mu_i)^2\}}$$

$$\tilde z^j_i=\frac{z^j_i-\mu_i}{\sigma_i}$$

⚠️ **两个"notation abuse"，老师自己点破了**：

- [11:56]–[12:04]：**「这边的 μ 它是一个 vector」** —— 不是把所有数字拉平算一个大平均，而是**同一个 dimension 一个分量**；「我们就把 `z1 z2 z3` 这三个 vector 把它平均起来得到 μ 这个 vector」。
- [12:12]–[12:29]：平方和开根号**都是逐 element 做**，「这边的平方，这个 notation 有点 abuse，这边平方就是指**对每一个 element 都去做平方**，然后再开根号」。
- [13:00]–[13:17]：除号也是 abuse，「这边的 μ 跟 σ 它都是 vector，所以我这边**除的意思是说 element-wise 的相除**」。

⇒ 直觉说法：**"同一个 dimension 的 Σ、减、除，各做各的"** —— 不同 dimension 之间**从不互相加减**（这一点在 §5 会变得很重要）。

## §5 ⭐ 一个巨大的 network：为什么它叫 Batch Normalization

### 5.1 最反直觉的一段：做 normalization 会让 example 彼此关联（[14:02]–[16:11]）

[14:02]–[14:12] 先埋伏笔：「这边的 μ 跟 σ，它们其实都是**根据 `z1 z2 z3` 算出来的**。」

然后 [14:14]–[15:06]：

> 「如果我们没有做 feature normalization 的时候，你改变了 `z1` 的值，你会改变这边 `a` 的值；**但是现在，当你改变 `z1` 的值的时候，μ 跟 σ 也会跟着改变**，μ 跟 σ 改变以后，`z2` 的值、`a2` 的值、`z3` 的值、`a3` 的值**也会跟着改变**。」

> 「所以之前我们每一个 `x̃1 x̃2 x̃3`，它是**独立分开处理**的；但是我们在做 feature normalization 以后，**这三个 example 它们变得彼此关联了**。」

⇒ 于是整个 process 的形状变了 [15:08]–[16:09]：

> 「你要把这**一整个 process**，就是有**收集一堆 feature、把这堆 feature 算出 μ 跟 σ** 这件事情，**当做是 network 的一部分**。」
> 「你之前的 network 都只**吃一个 input、得到一个 output**；现在你有一个**比较大的 network**，这个大的 network 它是**吃一堆 input**，用这堆 input 在 network 里面要算出 μ 跟 σ，然后接下来**产生一堆 output**。」
> ⭐ [15:54]–[16:11]：「这一段我觉得**只可意会不可言传**……就是现在不是**一个 network 处理一个 example**，而是**有一个巨大的 network，它处理一把 example**，用这把 example 还要算个 μ 跟 σ，**得到一把 output**。」

![P48_03_mu与sigma取决于zi_一个巨大的network_p7](P48_03_mu与sigma取决于zi_一个巨大的network_p7.webp)

> 图注（投影片 **p7**，标题 `Considering Deep Learning`，红字 `This is a large network!`）：⭐ **这张图就是"巨大的 network"那句话的图形版** —— 注意**红框把整个流程框起来了**，说明"框里全部 = 一个 network"。
> 流程：`x̃¹x̃²x̃³ → W¹ → z¹z²z³`，然后 ⭐ **从 `z¹`、`z²`、`z³` 同时引出黑线汇聚到黄色的 `μ`**（左下角标 `μ and σ depends on z^i`），μ 再连到绿的 `σ`；**μ 和 σ 又各自引线发回 `z̃¹`、`z̃²`、`z̃³`**（右上，公式 `z̃^i = (z^i − μ)/σ`）；再各自过 `Sigmoid` 得 `a¹a²a³`。
> ⚠️ **图上一堆黑框 `Δ`**：表示"**这里要算梯度**" —— 它在提醒你，反向传播时**不能把 μ/σ 当成常数**（μ/σ 是从这一把 z 算出来的，这条依赖也得算进去）；PyTorch 的 autograd 会自动把它展开。**这是 §5.1 那段"彼此关联"在计算图上的样子。**
> 右下角红字：`Consider a batch` / `Batch Normalization`。

### 5.2 为什么叫 "Batch"：因为一整个 dataset 装不进去（[16:11]–[17:19]）

[16:13]–[16:52]：

> 「因为你的 training data 里面你的 data 非常多……现在一个 data set **都上百万笔资料**，你哪有办法**一次把上百万笔资料丢到一个 network 里面**？你这个 **GPU 的 memory 根本没有办法**……把整个 data set 的 data 都塞进去。」
> 「所以怎么办？在实作的时候，你不会让这个 network 考虑整个 training data 里面的所有 example，你**只会考虑一个 batch 里面的 example**。」

[16:52]–[17:19]：

> 「举例来说你 batch 是 **64**，你这个巨大的 network 就是把 **64 笔 data 读进去**，算这 64 笔 data 的 μ、算这 64 笔 data 的 σ，对这 64 笔 data 都去做 normalization。因为我们在实作的时候，我们**只对一个 batch 里面的 data 做 normalization**，所以这招叫做 **batch normalization**。」

⚠️ **代价 / 限制** [17:23]–[17:57]：

> 「这个 batch normalization 显然有一个问题，就是**你一定要有一个够大的 batch**，你才算得出 μ 跟 σ。假设你今天 batch size 设 **1**，那你就**没有什么 μ 或 σ 可以算**。」
> 「因为 batch size 如果比较大，也许这个 batch size 里面的 data**就足以表示整个 corpus 的分布**，那这个时候你就可以把这个本来要对整个 corpus 做 feature normalization 这件事情，**改成只在一个 batch 做 feature normalization 作为 approximation**。」

⇒ 📌 **一句话**：**BN 是"对整个 dataset 做标准化"的廉价近似，代价是你得相信一个 batch 能代表整个 corpus。**

### 5.3 γ 与 β：把"均值必须是 0"这个限制松开（[18:02]–[20:12]）

[18:02]–[18:29] 公式：

$$\hat z^j_i=\gamma_i\cdot\tilde z^j_i+\beta_i\qquad(\text{乘、加都是 element-wise})$$

> 「你会把这个 `z̃` 再**乘上另外一个向量叫做 γ**……把 `z̃` 这个向量里面的 element 跟 γ 这个向量里面的 element **两两做相乘**，再加上 β 这个向量，得到 `ẑ`。」

⭐⭐ **它们是参数** [18:29]–[18:37]：

> 「而 **β 跟 γ 你要把它想成是 network 的参数，它是另外再被学出来的**。」

**为什么要加** [18:40]–[19:12]：

> 「因为有人可能会觉得说，如果我们做 normalization 以后，那这边的 `z̃` 它的**平均就一定是 0**，那也许今天如果平均是 0 的话，**就是给 network 一些限制**，那也许这个限制会带来什么负面的影响。所以我们把 β 跟 γ **加回去**，然后让 network 现在它的 hidden layer 的 output **不需要平均是 0** —— 如果它想要平均不是 0 的话，**它就自己去学这个 β 跟 γ 来调整一下输出的分布**。」

⭐ **老师自问自答的那个反问** [19:12]–[19:32]：

> 「这个刚才不是说做 batch normalization 就是为了要让每一个不同的 dimension 它的 **range 都是一样**，我们才做这个 normalization 吗？现在如果加去乘上 γ 再加上 β，**这样不会不同 dimension 的分布它的 range 又都不一样了吗？**」

答案 [19:32]–[20:12]：

> 「**有可能。** 但是实际上你在训练的时候，这个 **γ 跟 β 的初始值**，你会把这个 γ 的初始值就都设为 **1**（所以 γ 是一个 **one vector**、都是 1 的向量），那 β 是一个 **zero vector**、里面的值都是 0 的向量。」
> 「所以让你的 network **在一开始训练的时候**，每一个 dimension 的分布是**比较接近**的；也许训练到后来，你已经训练够长的一段时间、**已经走到一个比较好的地方以后**，那再把 γ 跟 β 慢慢加进去。」

⇒ 📌 **记住这条"先标准化、后放开"的设计哲学**：**初始值 γ=1、β=0 ⇒ 一开始"老实做标准化"；要不要偏离，交给训练自己决定。**

![P48_04_BatchNormalization_gamma与beta_p8](P48_04_BatchNormalization_gamma与beta_p8.webp)

> 图注（投影片 **p8**，标题 `Batch normalization`，**紧接 p7 的下一页**）：跟 `P48_03` 相比，右边**多出了两列 —— 黄的 `β`、绿的 `γ`，以及最后那一列 `ẑ¹ ẑ² ẑ³`**；右上角也多了一行公式 **`ẑ^i = γ ⊙ z̃^i + β`**（`⊙` = element-wise 相乘）。
> ⚠️ **两页的差别就是本集的"加法"**：p7 讲到 `z̃` 为止（**Batch Normalization 本身**），p8 才补上 **γ/β 这一层**。看图时**注意 γ/β 也各自从整排 `z̃` 收线过来** —— 它们跟 μ/σ 一样是"整排共用"的，只不过 μ/σ 是**算出来的**，γ/β 是**学出来的**。

### 5.4 Testing 怎么办：没有 batch，就用移动平均（[20:16]–[22:59]）

先立场景 [20:37]–[21:13]：

> 「在 testing 的时候当然如果今天你是在做作业，我们**一次会把所有的 testing 的资料给你**，所以你确实也可以在 testing 的资料上面制造一个一个 batch。但是假设你真的有系统上线，你是一个**真正的线上的 application**，你可以说我今天一定要等……**我一定要等 64 笔资料都进来，我才一次做运算吗？这显然是不行的。**」
> 「如果你是一个线上的服务，**一笔资料进来你就要每次都做运算**，你不能等说我累积了一个 batch 的资料才开始做运算。」

但问题来了 [21:15]–[21:35]：

> 「但是在做 batch normalization 的时候……你的 `z` 要**减掉 μ 跟除 σ**，那这个 μ 跟 σ 是**用一个 batch 的资料算出来的**。但如果今天在 testing 的时候**根本就没有 batch**，那我们要怎么算这个 μ 跟怎么算这个 σ 呢？」

**解法** [21:38]–[22:59]：

> 「如果你看 PyTorch 的话，batch normalization 在 testing 的时候，**你并不需要做什么特别的处理，PyTorch 帮你处理好了**。」
> 「它说在 training 的时候……你**每一个 batch 计算出来的 μ 跟 σ，它都会拿出来算 moving average**。你每一次取一个 batch 出来的时候你就会算一个 μ¹，取第二个 batch 出来的时候你就算个 μ²，一直到取第 t 个 batch 出来的时候你就算一个 μᵗ。接下来你会算一个 **moving average**……叫做 μ̄ **乘上某一个 factor**（那这也是一个**常数**、也是一个 **hyperparameter**、也是需要调的那一种），**在 PyTorch 里面我没记错它就设 0.1**，然后加上 **1−p 乘上 μᵗ**，然后来更新你的 μ 的平均值。」

公式（投影片写的）：

$$\bar\mu\leftarrow p\,\bar\mu+(1-p)\,\mu^t$$

> 「然后最后在 testing 的时候，你**就不用算 batch 里面的 μ 跟 σ 了**……你就直接拿 **μ̄ 跟 σ̄**，也就是 μ 跟 σ 在训练的时候得到的 moving average，**来取代这边的 μ 跟 σ**。这个就是 batch normalization 在 testing 的时候的运作方式。」

![P48_05_Testing_movingAverage](P48_05_Testing_movingAverage.webp)

> 图注（投影片 `Batch normalization – Testing`）：上半画的是**问题时态** —— `x̃ → W¹ → z`，`z̃ = (z − μ)/σ` 里的 **μ 和 σ 被红笔画掉**，改成蓝色的 **μ̄ 和 σ̄**，下面一行是那个反问 **`μ, σ are from batch?`**（`batch` 还特意加了粗体 + 下划线）。
> 下半是**答案**：`We do not always have batch at testing stage.` ＋ `Computing the moving average of μ and σ of the batches during training.` 下面把训练时算出的 `μ¹ μ² μ³ …… μᵗ` 一路排开，最后给出 **`μ̄ ← pμ̄ + (1−p)μᵗ`**。
> ⚠️ **两点提醒**：① **σ 也是一样处理的**（投影片只写了 μ 的式子，老师口述里是「μ 跟 σ 都算 moving average」，[21:57]–[22:04]）；② **p 是超参数**，别把"0.1"当成定理。

### 5.5 小节：BN 一层的完整流程（整理）

```
训练时（一个 batch 的 n 笔资料一起走）：
   z^j  ──(同 dimension 跨 n 笔算 μ, σ)──▶  z̃^j = (z^j − μ) / σ  ──(×γ, +β)──▶  ẑ^j  ──▶ activation ──▶ 下一层
   （同时把这一轮的 μ^t、σ^t 记下来更新 μ̄、σ̄）

测试时（一笔资料也能走）：
   z  ──(用训练期间累积的 μ̄, σ̄，不算 batch)──▶  z̃  ──(同一组 γ, β)──▶  ẑ  ──▶ ……
```

## 原始论文的实验：BN 到底带来什么（[23:03]–[25:50]）

老师先划范围 [23:11]–[23:23]：

> 「今天还没有讲的是，**batch normalization 用在 CNN 上要怎么用呢？那你自己去读一下原始的文献**，它会告诉你说 batch normalization 如果用在 CNN 上应该要长什么样子。」

图的读法 [23:25]–[23:46]：

> 「横轴代表的是**训练的过程**，纵轴代表的是 **validation set 上面的 accuracy**……这条**黑色的虚线是没有做 batch normalization 的结果**，它用的是 **Inception** 的 network。」

结果 [23:49]–[24:31]：

> 「如果有做 batch normalization，你会得到**红色的这一条虚线**……红色这一条虚线它**训练的速度显然比黑色的虚线还要快很多**。虽然最后收敛的结果……可能都跑到差不多的 accuracy，但是红色这条虚线可以在**比较短的时间**内就跑到一样的 accuracy。」
> 「这边的**蓝色菱形**代表说这几个点的 accuracy 是一样的了……红色的大概在**一半以内的时间**（相较于没有做 batch normalization），只需要一半或甚至更少的时间就跑到同样的正确率了。」

**sigmoid 那条** [24:35]–[25:08]：

> 「粉红色的线是什么呢？粉红色的线是 **sigmoid function**……一般都会选择 **ReLU** 而不是用 sigmoid function，因为 sigmoid function 它的 training 是比较困难的。但是这边想要强调的点是说，**就算是 sigmoid 比较难搞的，加 batch normalization 还是 train 得起来**。」
> 「那这边**没有 sigmoid 没有做 batch normalization 的结果** —— 因为在这个实验上，**作者有说 sigmoid 不加 batch normalization 根本连 train 都 train 不起来**。」

**蓝线的两条** [25:11]–[25:39]：

> 「蓝色的实线跟蓝色的虚线，是把 **learning rate 设比较大一点**：**乘 5** 就是 learning rate 变原来的 5 倍，**乘 30** 就是变原来的 30 倍。因为如果你做 batch normalization 的话，你的 error surface 会比较**平滑**、比较容易训练，所以你就可以把你的 learning rate 设大一点。」

⚠️ **那个"怪怪的"地方** [25:36]–[25:46]：

> 「这边有个**不好解释的奇怪的地方**，就是不知道为什么 learning rate 设 **30 倍**的时候是比 **5 倍差**，那**作者也没有解释**。你知道做 deep learning 就是，有时候会产生这种**怪怪的不知道怎么解释的现象**就是了。作者就是照实把它做出来的实验结果呈现在这个图上面。」

![P48_06_原始paper实验_BNx5_BNx30_Bnx5Sigmoid](P48_06_原始paper实验_BNx5_BNx30_Bnx5Sigmoid.webp)

> 图注（投影片 `Batch normalization`，右上角给出 **`Original paper: https://arxiv.org/abs/1502.03167`**）：纵轴 accuracy 0.4–0.8、横轴 0–30M 步。**五条线 + 一种标记**：
> `—— Inception`（**黑虚线**，无 BN 的基线，走得最慢）｜`–·– BN-Baseline`（**红点划线**，加了 BN）｜`···· BN-x5`（**蓝点线**）｜`—— BN-x30`（**蓝实线**）｜`····+ BN-x5-Sigmoid`（**粉线**，Sigmoid + BN ×5 —— 它能跑起来本身就是结论）｜**蓝色菱形 `Steps to match Inception`** = "跑到跟黑虚线同等 accuracy 所需的步数标记"。
> ⭐ **读图三件事**：① **红点划线在 ~13M 步就到了黑虚线 ~30M 步的水准**（菱形标记都在同一水平线上）；② **蓝实线（×30）在 ~7M 步后就不动了，且最终低于蓝点线（×5）** —— 这就是老师说的"30 倍比 5 倍差、作者也没解释"；③ ⚠️ **这张图上根本没有"Sigmoid 无 BN"的线**，因为**它 train 不起来**。

## §7 它为什么有用：internal covariate shift 与其被打脸（[25:50]–[28:44]）

### 7.1 原论文的说法（[25:50]–[27:13]）

[25:57]–[26:14]：

> 「在原始的 batch normalization 那篇 paper 里面，它提出一个概念叫做 **internal covariate shift**。**covariate shift 这个词汇是原来就有的**，**internal covariate shift 我认为是 batch normalization 的作者自己发明的**。」

论点 [26:19]–[27:01]：

> 「network 有很多层，`x` 通过第一层以后得到 `a`，`a` 通过第二层以后得到 `b`。那我们今天计算出 gradient 以后，把 `A` update 成 `A'`，把 `B` 这一层的参数 update 成 `B'`。但是作者认为说，现在我们在把 `B` update 到 `B'` 的时候……**这个时候前一层的参数是 `A`**……那当前一层从 `A` 变成 `A'` 的时候，它的 output 就从小 `a` 变成小 `a'`。**但是我们计算这个 gradient 的时候，我们是根据这个 `a` 算出来的** —— 所以这个 update 的方向，**也许它适合用在 `a` 上，但不适合用在 `a'` 上面。**」

[27:04]–[27:13]：

> 「那如果做 batch normalization 的话，我们会让……`a` 跟 `a'` 它的**分布比较接近**，也许这样就会对训练有帮助。」

### 7.2 打脸的那篇（[27:15]–[28:16]）

[27:15]–[27:41]：

> 「但是有一篇 paper 叫做 ***How Does Batch Normalization Help Optimization?***，那它就**打脸**了 internal covariate shift 的这个观点。在这篇 paper 里面，它从各式各样的面向来告诉你说：internal covariate shift **首先它不一定是 training network 的时候的一个问题**；然后 batch normalization 它会比较好，**可能不见得是因为它解决了 internal covariate shift**。」

它做的三个实验 [27:43]–[28:13]：

> 「比如说它比较了训练的时候，这个 `a` 的**分布的变化**，发现**不管有没有做 batch normalization，它的变化都不大**；然后它又说**就算是变化很大，对 training 也没有太大的伤害**；然后它又说，不管你是**根据 `a` 算出来的 gradient，还是根据 `a'` 算出来的 gradient，方向居然都差不多**。」
> 「所以它告诉你说，internal covariate shift 可能**不是** training network 的时候最主要的问题，它可能也**不是** batch normalization 会好的一个关键。」

![P48_07_InternalCovariateShift被打脸_p11](P48_07_InternalCovariateShift被打脸_p11.webp)

> 图注（投影片 **p11**，标题 `Internal Covariate Shift?`，副标题 `How Does Batch Normalization Help Optimization?`，右上角 **`https://arxiv.org/abs/1805.11604`**）：**上排是"更新前"** —— `x → A → a → B → b`；**下排是"更新后"** —— `x → A' → a' → B' → b'`：两条虚线箭头各标一个 `update`。
> ⭐ **关键标注在 `a → B` 那条虚线上**：**`Good for a, But not for a′`** —— 说的正是 §7.1 那句"gradient 是照着 `a` 算的，却要用在 `a'` 上"。
> 底部两行是**结论**：`Batch normalization make a and a′ have similar statistics.`（这是**原论文的主张**）＋ **`Experimental results do not support the above idea.`**（这是**这篇论文的判决**）。
> ⚠️ **别把两篇看成一篇**：**提出 ICS 的是 BN 原论文**（`1502.03167`，那张图就是它）；**打脸的是 `1805.11604`**。⚠️ 老师说标题时口误成「How does **specialization** help optimization」[27:15]、又说成「how does **batch normalization** help optimization」[28:25] —— **以投影片与 arXiv 编号为准**。

### 7.3 那篇支持的结论 + serendipitous（[28:20]–[30:18]）

[28:20]–[28:44]：

> 「那为什么 batch normalization 会比较好呢？那在这篇 *How does batch normalization help optimization* 这篇论文里面，它从**实验上也从理论上至少支持了** batch normalization 可以**改变 error surface、让 error surface 比较不崎岖**这个观点。所以这个观点是**有理论的支持、也有实验的佐证**的。」
> （⚠️ 措辞是"**至少支持了**" —— 不是"证明了"。）

⭐ **serendipitous** [28:46]–[30:14]：

> 「作者还讲了一个非常有趣的话。他说他觉得这个 batch normalization 的 positive impact —— 因为他说如果我们要让 network 的 error surface 变得比较不崎岖，其实**不见得要做 batch normalization**，感觉**很多其他的方法都可以让 error surface 变得不崎岖**。那他就试了一些其他方法，发现说**跟 batch normalization performance 差不多，甚至还稍微好一点**，所以他就讲了下面这句感叹：」
> 「他觉得说这个 **positive impact of batch norm on training 可能是 somewhat serendipitous。**」
> 「什么是 serendipitous 呢？这个字眼可能可以翻译成**偶然的**，但**偶然并没有完全表达这个词汇的意思**。这个词汇的意思是说：**你发现了一个什么意料之外的东西。**」
> 「举例来说，**盘尼西林**就是意料之外的发现……弗莱明他本来想要培养一些葡萄球菌，然后但是因为他实验没有做好，他的葡萄球菌被感染了，有一些霉菌掉到他的培养皿里面，他发现那些霉菌会杀死葡萄球菌，所以他就发现了盘尼西林。所以这是一种**偶然的发现**。这篇文章的作者也觉得，**batch normalization 也像是盘尼西林一样，是一种偶然的发现。但无论如何它是一个有用的方法。**」

⇒ 📌 **本节最该带走的两句话**：
1. **BN 有效的机制**：**改变 error surface**（有理论 + 实验支持）—— **不是** ICS。
2. **BN 的地位**：它是一个**意外发现的好方法** —— 而且**别的办法也能达到同样的效果**，甚至稍好一点。

## §9补充图：第一层到底有几个 `w`（回答"`W` 是不是那一层的 w"）

> ⚠️ **这一节是补充的，不是老师投影片的内容。** 起因是 2026-10-03 用户的一个真问题（见核对记录 Q6）。

**问题**：`P48_02` 里每个 `x` 都连到同一个方块 `W¹` —— 是"**一个 w 同时考虑多个 feature**"，还是"**每个 w 只管各自的那个 feature**"？那个大 `W` 是"那一层的 w"吗？

**答案**：**每个 w 只管一个 x；一层里所有的 w 合起来才是 `W¹`。** 具体到 `P48_02` 那张图（3 个输入进、3 个输出出）：

```
z¹ = x̃¹·w₁₁ + x̃²·w₁₂ + x̃³·w₁₃ + b₁
z² = x̃¹·w₂₁ + x̃²·w₂₂ + x̃³·w₂₃ + b₂
z³ = x̃¹·w₃₁ + x̃²·w₃₂ + x̃³·w₃₃ + b₃
```

⇒ **每条连线各有一个自己的 w ⇒ 3×3 = 9 个 w，再加 3 个 b**。这 9 个数排成 3 行 3 列、**一起打包**就是投影片上那个 `W¹` 方块。

- **"每个 w 只考虑各自的 feature" ✅**（对**单个 w** 而言：`w₁₂` 这辈子只乘 `x̃²`）；
- **"所有 feature 都连到同一个 `W¹`" ✅**（对**整层**而言：整层共用**同一张表**，但这张表里**装着 9 个不同的数**，不是"9 个输入乘同一个数"）。

⚠️ **一个容易读错的地方**：这张图里**上标是"第几笔资料"**（`z¹ z² z³` = 一个 batch 里三笔资料过完第一层的结果，所以老师 [11:58] 才说"这三个 **vector**"）；**"第几层"是写在 `W` 上的**（`W¹` 第一层、`W²` 第二层）。

⭐⭐ **顺带分清"共享"的三种场合**（用户原以为是"所有 feature 连同一个 w"，多半是下面两处的印象）：

| 场景 | 一个 `w` 被谁共用 | 出处 |
|---|---|---|
| **全连接层**（本集这张图） | **不共享**：每条连线一个专属 `w` | 本节 |
| **CNN 的 filter** | **共享**：同一张 filter 的 w 扫过**图片的每个位置** | [[第31集_卷积神经网络\|第31集]] |
| **self-attention 的 `Wq/Wk/Wv`** | **共享**：**每个位置**都用同三张表 | [[第39集_自注意力机制(下)\|第39集]] §2.5 |

⭐ **这一节还顺手解释了 §2.3 为什么要标准化**：既然 `z¹` 是**加起来**的，那 `x̃²` 若比 `x̃¹` 大 100 倍，`w₁₂` 动一点 `z¹` 就大动、`w₁₁` 动同样多几乎没反应 ⇒ **同一层里不同 w 的"敏感度"差 100 倍** ⇒ 误差表面在不同方向坡度差很大（就是 `P48_01` 那张 `steep`/`smooth` 图）。

![P48_09_第一层全连接展开_9个w与3个b](P48_09_第一层全连接展开_9个w与3个b.png)

> 图注（**补充图**，不是老师投影片）：左边三个 `x̃` 进来、右边三个 `z` 出去，中间橙色 `W¹` 方块代表"**这一层要学的参数**"（9 个 w + 3 个 b）；**右边逐个数写出三个式子**；**下方把 `W¹` 拆开成 3×3 的九宫格**（`w₁₁`–`w₃₃`），并标出"**每一行 = 一个输出用的那组 w**""**每一列 = 一个输入被 3 个输出各拿走一个 w**"；**右下角对照三种"共享"场合**（全连接层 / CNN filter / self-attention 的三张表）。
