## 二、核心概念

### 2.1 这一集要回答的问题（以及它的答案长什么样）

一句话版：**validation set 也是"一组抽样出来的资料"，它一样会被抽坏**；而它被抽坏的机率**由你自己决定**（你比了几个候选）。

- ⚠️ **注意"还是 overfit 了"指的是哪一段**：[00:31]–[00:38]「用了 validation set 以后，把结果传到 leaderboard 上，在 testing set 上却还是 overfitting 了」⇒ 你**在 D_val 上挑出来的那个赢家，到 testing set / D_all 上不灵了**。
- ⚠️ 这一集**不是**在说"validation set 没用" —— ②的流程本身没错，问题出在你**把 D_val 用得太狠**（⑦）。

### 2.2 ⭐ 转念：用 validation 选模型 = 在 D_val 上做一次 "training"

![[P32_01_复习页_三模型训练与验证集选择.png]]
> 图注（[00:43]–[05:26]）：**这张就是本集的"复习页"，也是全集的枢纽**。**左上（Training Set 𝓓_train）**= 三个模型各自在 D_train 上解出 `hᵢ* = arg min_{h∈𝓗ᵢ} L(h, 𝓓_train)`；**右上（Validation Set 𝓓_val）**= 把三个 h\* 拿来量 loss：**0.9 / 0.7 / 0.5**，最低的 **0.5 被红框圈起来**（⇒ 选 h₃\*）。**页面下半**把这件事重写成一个新的挑选问题：**𝓗_val = {h₁\*, h₂\*, h₃\*}**、`h* = arg min_{h∈𝓗_val} L(h, 𝓓_val)`。**最下面的黑框就是本集的题眼**：**"Using validation set to select model = considered as ''training by 𝓓_val''；Your model is 𝓗_val = {h₁\*, h₂\*, h₃\*}"**。

为什么这叫"一次 training"？因为 [04:46]–[04:56] 老师先给了一句 training 的白话定义：

> 「我们一般在做 training 的时候，你就是要**找一个 function 在某一组 data 上**，它的 **loss 最低**，这就是你的 training 嘛。」

而这个动作**一字不差**地发生在 D_val 上：在 𝓗_val 里找一个 h，让 D_val 上的 loss 最低。

- ⚠️ **为什么要加双引号**（[04:28]–[04:36]）：它**不是** gradient descent 那种 training（不是用梯度下降去调网络里的参数），而是**在 3 个候选里直接挑一个** —— 老师原话「所以我们这边呢加一个双引号」。
- ⭐ **这个"新 model"小得可爱**（[03:57]–[04:09]）：「这个 model 里面**只有三个可能的 function**」；对比「一般的 model，假设你的 model 是一个 deep 的 network，那你可以选择的 function 当然是成千上万，是个天文数字」。

### 2.3 ⭐⭐ 两个 `|𝓗|` 的分工（本集最该带走的一张表）

两条式子长得几乎一样，但**乘号左边那个"复杂度"根本不是同一件东西**：

| | 第一条式子（P23 的原式） | 第二条式子（本集新写的） |
|---|---|---|
| 写的是 | `P(𝓓_train is bad) ≤ \|𝓗\|·2exp(−2Nε²)` | `P(𝓓_val is bad) ≤ \|𝓗_val\|·2exp(−2N_val ε²)` |
| 左边的"复杂度"指 | **每个模型类自己有多大**（这个网络能表示多少种 function） | **你拿出来比了几个候选**（这个例子里就是 **3**） |
| 资料量是 | **N**（训练集大小） | **N_val**（验证集大小） |
| 它管的事 | ⭐ **你训出来的那个 h\* 靠不靠谱**（落差） | ⭐ **你比出来的名次靠不靠谱** |
| 谁把它撑大 | **模型容量**（H₁/H₂/H₃ 里最大的那个） | **你自己试了几组**（[07:28]–[08:29] 的 hyperparameter 搜索） |

⇒ ⭐⭐ **一句话**：**H₃ 的容量再大，它在 𝓗_val 里也只占"1 票"。** 模型有多大 ≠ 你比了几个。

### 2.4 什么把 `|𝓗_val|` 撑大：你自己试了几组

[07:37]–[08:19] 老师给的例子（**这一段是本集唯一的新内容，前六段都只是复习**）：

> 「你今天 H_val 太大……你想要决定你的 hyperparameter，比如说**网络架构**的时候，你做得太猛……我说这个网络架构要从**一层到十层**，那每一层要有多少个 neuron 呢？我想是**一到一千**……我决定跑这个 **1000¹⁰** 个模型……那这个时候你的 **H_val 就有 1000¹⁰ 那么大**……那你也很有可能会 overfitting。」

- ⚠️ **直觉**：这三层选择（层数、每层 neuron 数、然后挑最好那组）本质上是**在 D_val 上做了一次 1000¹⁰ 选 1 的挑选** ⇒ 那个"赢家"完全可能只是**恰好在这组 D_val 上运气好**。
- ⭐ **和 P23 的对应**：`|𝓗|` 变大 → "抽到坏资料"的机率上界变大（P23 §3.5「How to make P(D_train is bad) smaller? → **Larger N and smaller |𝓗|**」）—— 现在把 D_train 换成 D_val、𝓗 换成 𝓗_val，**整句话一字不改地成立**。

### 2.5 为什么"通常"没事：It is small. Hopefully……

老师在投影片上用箭头指着 `|𝓗_val|` 写了 **"It is small. Hopefully……"**（见 §3.1 的 `P32_02`），对应 [07:10]–[07:28] 这段话：

- **通常**：你只是拿几个现成的模型来比（3 个、10 个），`|𝓗_val|` 很小 ⇒ 这条上界很紧 ⇒ **validation 是可信的**；
- **但是**：「它会不会很小呢？那就取决于**你怎么设计你的实验**了」—— 旋钮在你手上。
- ⇒ **所以这一集的答案不是"validation 不可靠"，而是"validation 的可靠性有前提，而那个前提由你的实验规模决定"。**

## 三、公式与推导要点

### 3.1 同一个不等式，换一次下标

![[P32_02_两条不等式_H与Hval的分工.png]]
> 图注（[05:26]–[08:52]）：**本集的落点页**。顶部黑框是 §2.2 那句题眼（"Using validation set to select model = considered as 'training by 𝓓_val'；Your model is 𝓗_val = {h₁\*, h₂\*, h₃\*}"）。下面**两条不等式并排**，**形状完全一样、只换了右下角的下标**：第一行 `P(𝓓_train is bad) ≤ |𝓗|·2exp(−2Nε²)`（= P23 的原式），第二行 `P(𝓓_val is bad) ≤ |𝓗_val|·2exp(−2N_val ε²)`；箭头 `↑` 指在 **`|𝓗_val|`** 上，底下写着 **"It is small. Hopefully……"**。最下面一行是这一集的结论：**"If your |𝓗_val| is large, you still have high P(𝓓_val is bad)."**

| 第一层（[[第23集_再探分类器与机器学习原理|P23]] 的原式） | 第二层（本集新写的） |
|---|---|
| 资料集 **D_train** | **D_val** |
| 资料量 **N** | **N_val** |
| 候选集合 **𝓗**（这个模型能选的所有 function） | **𝓗_val = {h₁\*, h₂\*, h₃\*}**（我拿出来比的那几个） |
| "training" = 在资料上挑 loss 最低的 function | **在 D_val 上挑 loss 最低的那个 h\***（[03:48]–[05:12]） |
| 结论：坏的 training set ⇒ 理想与现实差距大 | **坏的 validation set ⇒ 你看到的名次跟真相差距大** |

⚠️ **记号**：本集与 P23 用同一套记号（**ε** = 你能接受的差距、**δ** = 你能接受的机率）。⚠️ 两条式子里**两个 N 不是同一个 N**（`N` = 训练集大小、`N_val` = 验证集大小）。

### 3.2 为什么 `|𝓗_val| = 3`：union bound 的"项数"再解释一次

（这一节是把 P23 §3.3 的 union bound 原样搬到这一层，用 P23 的结论直接读。）

- **"坏 validation set" 的定义**（照搬 P23 的定义方式）：**存在**某个候选 h ∈ 𝓗_val，使得"它在 D_val 上量到的表现"与"它在 D_all 上的真实表现"差超过 ε ⇒ 写成**并集 ∪**。
- **并集算不动 → 改成连加**（union bound），每一项再用 Hoeffding 给上界 ⇒ 因为上界 **跟是哪个 h 无关**，求和退化成「**项数 × 每项**」。
- ⭐⭐ **"两层为什么不一样"的通用判据（2026-09-24 用户订正后长出来的）**：**被量的 h，是不是被"用来量的那组资料"选出来的？**
  - **第一层（P23）**：`h^train` **是**被 D_train 选出来的 ⇒ **自指** ⇒ 它在 D_train 上的成绩"自带水分"，所以理论里必须拿"跟资料无关的固定 h"来分组（＝ union bound 里那些 h）。
  - **第二层（本集）**：`hᵢ*` **不是**被 D_val 选出来的（它只见过 D_train）⇒ **不自指** ⇒ D_val 对它是"**没见过的新资料**"，量出来就是"现实"。⭐ **这就是"两层不一样"的全部内容，也是 `|𝓗_val| = 3` 站得住的唯一理由。**
  - ⚠️ **方向别读反**：**随机的是资料、固定的是 h**。老师口语说"h 去弄坏资料"是**倒装**，精确说法是"**资料把 h 量歪**"（这个坑 P23 QA Q5 已经确认过一次）。
  - ⚠️ **D_val 从哪来**：实务上是把**到手的那批资料切成 D_train / D_val 两块**（P18 讲的就是这件事）—— 别写成"D_val 是 D_train 的一部分"，那会跟"h\* 在 D_train 上训练"打架（会被读成"h\* 见过 D_val"）。⭐ **真正让第二条式子成立的不是"从哪切"，而是顺序**：**h\* 定好之后，D_val 才被拿去用**。
  - 🔍 **顺带堵一个反问**：「h\* 本来就可能是被坏 D_train 选歪的次品，D_val 会不会看不出来？」—— **看得出来**：h\* 真实水准差 ⇒ D_val 上的 loss 就高（D_val 对这个 h 是无偏的）。D_val 保证不了的是**名次**（`|𝓗_val|` 巨大时）。
- ⭐⭐ **补充（本集没说，但由上式直接推得）**：把这句话反过来读 —— **只要你看了 D_val 的结果回头改模型、再试一组，你就是把 D_val 的信息喂进了"候选是怎么产生的"这个过程**；此时"候选集合"不再是**比之前就固定**的 3 个，可以有效候选数只会一路往上涨。⇒ 这正是 [07:28]–[08:29] 那段 hyperparameter 搜索在做的事，也是**为什么会从"3 票"变成"1000¹⁰ 票"**。

### 3.3 ⭐ 补充：把 P23 的反解式也换一次下标

P23 还有一条反解式（要准备多少资料才够）：

```
P(坏资料) ≤ δ   ⇒   N ≥ log( 2|𝓗| / δ ) / (2ε²)
```

**换个下标**就得到本集的版本：`N_val ≥ log( 2|𝓗_val| / δ ) / (2ε²)`。代数字看看量级（⚠️ **上界很松，只看方向**，见 P23 §3.6）：

| 场景 | `\|𝓗\|` | 需要多少资料（ε = 0.1、δ = 0.1） |
|---|---|---|
| P23 的玩具模型 | 10⁴ | 约 **610** 笔 |
| 本集老师举的例子 | **1000¹⁰ = 10³⁰** | 约 **1.4 万** 笔 |

⇒ ⭐ **反直觉但重要**：因为式子里是 **log**，候选数从 10⁴ 涨到 10³⁰（26 个数量级），需要的资料只从 610 涨到约 1.4 万（**1 个多数量级**）。⇒ 这条式子**并不支持**"多试几组就一定完蛋"；它支持的是老师那句更保守的话：**上界不再是"必然可靠"，你仍然可能 overfitting**（而且真实情况往往比上界更糟 —— 上界只保证"不会更坏"）。

## 四、我的理解（2026-09-24：一轮提问 + 一轮我的订正）

### 4.1 我提的问题（照录，原文不改）

> 现在我们来写第32集的笔记，根据23集的理论，能不能从H3对应的模型表达能力（H3最大）是最强的（训练出的h导致模型在训练集上过拟合导致理想和现实差距过大）这个方面来理解

### 4.2 判定：⚠️ **对一半 —— 因果链对，但落点要挪一格**

**它解释的是「为什么需要 validation」，不是「为什么有了 validation 还会过拟合」（= 本集标题那个问题）。**

| # | 我原话里的部分 | 判定 | 订正 / 佐证 |
|---|---|---|---|
| 1 | "H₃ 模型表达能力最强（最大）" | ⚠️ **投影片没写** | 这一页只写了"三个模型 H₁/H₂/H₃"（[00:53]「假设你有三个模型」），**没有写 H₁ ⊂ H₂ ⊂ H₃**。"H₃ 最大"是**我们的读法**（编号顺序 + P18/P23 的语境），不是板书事实 —— 这么说没问题，但要知道这是补上去的。 |
| 2 | "训练出的 h 在训练集上过拟合" | ✅ **对，而且正是 P23 的机制** | 容量大 ⇒ 能选的 function 多 ⇒ 「抽到坏 D_train」的机率上界变大 ⇒ **h\* 在 D_train 上的漂亮成绩最不可信**（= P23 的"落差"）。 |
| 3 | "导致理想和现实差距过大" | ✅ **对**（这是 P23 的主句） | [05:44]–[05:49]「如果你**抽到一个不好的 training data** 的时候，你的**理想跟现实**会有你没办法接受的差距」；[06:05]–[06:19]「你的 model 的 complexity 有多大……可以选择的 function 的 candidate 有多少……越多……这种 training set 的机率就很大」。 |
| 4 | "（所以）能用这个来解释本集的问题" | ❌ **不行** | 三个理由 ↓ |

**三个理由**：

1. **图上 h₃\* 是赢家**：`L(h₃*, 𝓓_val) = 0.5`（**红框**）最低 ⇒ 这一页展示的**不是**"H₃ 因为过拟合而吃亏"，恰好是同一颗旋钮的**另一面**：**容量大 ⇒ 理想本身更低（地板更低）**。P23 的落点页写得很清楚：`Smaller |𝓗| ⟹ Larger L(h^all, 𝓓_all)`。⇒ **`|𝓗|` 大 = 地板低（好事）+ 落差大（坏事）**，我这次只说了坏的那一半。
2. **第二层的凶手不是 H₃ 的容量，是 `|𝓗_val|`**：投影片用箭头指着 `|𝓗_val|` 写 **"It is small. Hopefully……"**。`|𝓗_val|` 数的是**你比了几个候选**（这里 = 3），**不是每个候选背后的模型有多大**（见 §2.3 的表）。
3. **两层要分开**：**H₃ 的容量污染的是"你选出来的这个 h 好不好"，不是"你在 D_val 上量得准不准"。** h₃\* 在 D_val 上的 0.5 是**它没见过的资料**给的，所以这个数还是可信的 —— validation 干的就是这件事。

**正确版的读法**：

> `|𝓗|` 大 ⇒ **训练这一层的落差大**（所以你不能用 D_train 的成绩来比模型）⇒ **这就是为什么要有 validation**。
> 而 P32 讲的是：**再加一层选择，就再多一层落差** —— 这次用的资料是 D_val、候选集合是 `𝓗_val`；同一套理论再写一遍，`|𝓗|` 换成 `|𝓗_val|`、`N` 换成 `N_val`。
> ⭐ **H₃ 再大，它在 𝓗_val 里也只有一票；把 `|𝓗_val|` 撑大的是"你自己试了几组"。**

## 五、易错点与纠正

1. ⚠️ **最常混的一句**："用了 validation 还 overfit" **不是**因为"我的模型容量太大、在训练集上过拟合了" —— 那个落差**正是 validation 拿来抓的东西**（它抓得到）。这一集说的是：**你用来抓落差的那把尺子（D_val）自己也会被抽坏**，而抽坏的机率由 **`|𝓗_val|` + `N_val`** 决定。
2. ⚠️ **两个 `|𝓗|` 不是同一件东西**：一个是**模型有多大**（第一条式子），一个是**你比了几个**（第二条式子）。★ 见到 `|𝓗_val|` 先问"这是在数候选，还是在数容量"。
3. ⚠️ **"validation set 上的结果"不等于"真相"，它只是一次抽样** —— 这正是 P23 §3.5 那句话的第二次应用（P23 用在 D_train 上，本集用在 D_val 上）。
4. ⚠️ **不是"validation 没用"**：②的流程本身没错。老师最后一句限定得很清楚：「你**可选择的模型太多了**，你**仍然有可能**会 overfitting」—— 是**条件句**，不是"必然"。
5. ⚠️ **投影片的 0.9 / 0.7 / 0.5 是示意数字**：老师**没有**解释它们怎么来的、也没有说这是某个实验的结果（别把它当成"实测"引用）。
6. ⚠️ **"H₃ 最大"要标注来源**：见 §4.2 第 1 行。
7. ⚠️ **`|𝓗_val|` 大不等于"必然坏"**（§3.3 的补充）：式子里是 log，量级上很宽容；真正的意思是"你不再有保证"。
