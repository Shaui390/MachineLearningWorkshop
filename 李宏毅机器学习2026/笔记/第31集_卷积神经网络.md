## 一、本集讲了什么（大纲）

**一条主线**：图片太大 → 全连接参数爆炸 → 观察影像的两个特性 → 用它们换两个简化 → 得到 convolutional layer → 换个说法再讲一遍（filter/convolution）→ 加上 pooling 与末尾的全连接 → 看 AlphaGo 怎么按任务改架构。

| **② 任务设定** | [00:44]–[03:10] | 影像分类；输入大小固定（100×100）；one-hot 的 ŷ + softmax 的 y′ + cross entropy |

| **④ 问题：参数爆炸** | [05:45]–[07:19] | 第一层 1000 个 neuron → **3×10⁷ 个 weight**；弹性大 → 更容易 overfitting |

1. **开场**（[00:00]–[00:44]）：前面讲的都是"怎么训练一个网络"，从这集开始讲"**网络架构怎么设计**"。第一个变形就是 CNN —— 老师选择它做例子，是因为**从它身上能看清"架构设计"到底在做什么**：为什么改了架构，结果就会更好。

2. **任务设定**（[00:44]–[03:10]）：场景 = **影像分类**（给机器一张图，判断里面有什么）。两个前提：
   - ⭐ **输入图片大小固定**（例：100×100）。"就算今天 Deep Learning 已经这么 popular，我们往往都还是需要假设一个模型输入的影像大小都是一样的" [01:24]–[01:30]；长方形图片一律先 **rescale** 成同样大小 [01:38]–[01:47]。
   - 输出端沿用前面学过的：每个类别一个 **one-hot** 向量 ŷ，网络输出过 **softmax** 得 y′，最小化 **cross entropy** [01:51]–[03:08]。类别数 = 向量长度（1000、上万都常见）。
   - ⚠️ 字幕把 one-hot 听写成"one heart"、ŷ 听写成"y hand"、y′ 听写成"Wi-Fi"（见 §5.2）。

3. **影像对电脑是什么**（[03:10]–[05:39]）：
   - 一张图 = **三维 tensor**（"维度大于 2 的矩阵就是 tensor" [03:31]）。三维分别是 **宽、高、channel**；彩色图的 channel = RGB 三层；长宽 = 解析度。
   - 于是有 **100×100×3 = 30000 个数字**。
     ![[P31_01_影像分类_三维tensor拉直成向量.png]]
     > 图注：投影片把这条链一次画完 —— 左：原图 **100×100**；中：拆成 **3 个 channel**（`3 channels`）的 3-D tensor，每层各 100×100；右：把这 3 层摊成**三根直条**。页脚那句「**它的输入其实都是一个向量**」就是"拉直"的结论。⚠️ 投影片把拉直画成**三根并排的直条**，不是一根三万的细条 —— 同一个向量，只是排版不同。
   - ⭐ **拉直**：老师原话 [04:53]「最直觉的方法就是**直接拉直它**」—— 把这 30000 个数字**通通拿出来排成一排**，就是一个 30000 维向量，每一维存的 = **某一个位置的某一个颜色的强度** [05:14]–[05:39]。
   - 为什么要拉直？因为**到目前为止讲的 network 输入都是向量** [04:38]–[04:46]。
   - 补充：**"拉直"就只是"换个摆法"**，唯一要定的是**读取顺序**（最常用：从左到右读一行 → 换下一行 → 一个 channel 读完再读下一个）。⚠️ 顺序本身无所谓，**训练与测试用同一种**就行；课上没有讲这个约定。
   - ⭐⭐ **代价（补充，但正是全集的支点）**：排队之后"**谁挨着谁**"的信息就没了 —— 方块里上下左右相邻的数字，在长队里可能隔得很远。⇒ 后面进全连接层时，网络**看不出空间关系**，只能靠参数硬背。

4. **问题：参数爆炸**（[05:45]–[07:19]）：
   - 若把这个 30000 维向量丢进全连接层、第一层 1000 个 neuron ⇒ weight 数 = 1000 × 100 × 100 × 3 = **3×10⁷** [06:06]–[06:28]。
     ![[P31_02_全连接参数爆炸.png]]
     > 图注：投影片把 **3×10⁷** 直接标在"输入（100×100×3）→ 1000 个 neuron"那团连线上；页脚那一问「**Do we really need "fully connected" in image processing?**」就是本集余下全部内容的起点。
   - 参数越多 ⇒ 模型弹性越大 ⇒ **越容易 overfitting** [06:33]–[07:02]（"下周有老师会从数学上给清楚的证明" [06:52]）。
   - ⚠️ **病因不是"图片有 30000 个数字"，而是"每个 neuron 都连到每一个数字"**。老师原话 [07:21]–[07:27]（字幕缺字，已补）："我们其实**不需要**每一个 neuron 跟 input 的每一个 dimension **都有一个 weight**"。

5. ⭐ **观察一 → 简化一：Receptive Field**（[07:19]–[20:20]）
   - **观察**：判断"图里有没有一只鸟"，神经元要做的是侦测**关键 pattern**（鸟嘴、眼睛、鸟爪）。而这些 pattern **不需要看整张图**就能侦测到 [07:35]–[10:08]。
     - 老师插的例子：一张图里有"鸟嘴 + 眼睛"，看着像乌鸦，**其实是一只猫** —— 连人判断物件时也是抓最重要的特征 [08:46]–[09:16]。
       ![[P31_03_观察一_不必看整张图.png]]
       > 图注：投影片把"一小块"画得很具体 —— Layer 1 每个 neuron 上贴的是**原图的一个小截取**（鸟嘴、眼睛、鸟爪），它叫 **basic detector**；Layer 2 叫 **advanced detector**，最后才判断出 bird。三句英文就是这步论证：**Need to see the whole image?**（自问）→ **A neuron does not have to see the whole image.**（观察）→ **Some patterns are much smaller than the whole image.**（理由）。
   - **简化**：给每个 neuron 划一块**守备范围 = receptive field（RF）**，它只关心自己那块里发生的事 [10:45]–[11:30]。
   - neuron 怎么"看"那块？把 RF 里那 **3×3×3 = 27 个数字拉直成 27 维向量**当输入，给它 **27 个 weight + bias** [11:36]–[11:58]。
     ![[P31_04_简化一_receptive_field.png]]
     > 图注：投影片把 27 个数字画成**三根 3×3 的直条**（一个 channel 一根），虚线箭头指向右边**一个 neuron** —— 这就是"RF 那一小块被拉直、喂给一个 neuron"。
     - ⭐ 注意这里"拉直"是**第二次出现**，和 §2.1 的整图拉直是同一个动作 —— 但对象只有一小块。（补充：这是 CNN 与 FC 的关键分野，见 §3.1）
   - **RF 完全由你设计** [12:08]–[15:30]：可以大小不同、可以只看某些 channel、可以长方形、理论上也可以**不相连**（比如"左上角 + 右上角"两块）—— 但老师反问"**为什么你要这么做**"，因为 pattern 通常出现在**一个连续的位置**，所以实务上 RF 都是**相连的领地**。
     ![[P31_05_简化一_可配多个且可重叠.png]]
     > 图注：这页把"简化一"的两个**附带事实**一起画出来 —— 上半：**同一个 RF 上可以站一排 neuron**（`3 x 3 x 3 weights` 指向被括起来标注 `the same receptive field` 的那几个 neuron）；下半：**RF 之间可以重叠**（`Can be overlapped`）。⚠️ 这两件事**要等 §2.6 才被定成经典设定**（每 RF 配 64 个 neuron、stride 造成重叠），这里只是"可以这样做"。

6. **RF 的经典设定**（[15:34]–[20:20]）：

   | 设定 | 内容 | 出处 |
   |---|---|---|
   | 看全部 channel | 一般不认为"某个 pattern 只在某个 channel 出现"，所以默认看全部；⇒ 描述 RF 时**只讲高跟宽、不讲深度**，这个"高×宽"就叫 **kernel size** | [15:47]–[16:10] |
   | kernel size | 常用 **3×3**；7×7、9×9 算蛮大的 | [16:20]–[16:36] |
   | 一个 RF 配**一组** neuron | 不是 1 个，而是**一排**（例：**64 或 128 个**）—— 只用一个 neuron 没办法侦测所有 pattern | [13:01]–[13:20]、[17:05]–[17:25] |
   | **stride** | 把 RF 往右移一点得到下一个 RF，移动量叫 stride；**常见 1 或 2，不会设太大** —— 因为希望 RF 之间有**高度重叠** | [17:26]–[18:11] |
   | 为什么要重叠 | ⭐ **若完全不重叠，pattern 正好落在两个 RF 的交界上 → 没有任何 neuron 去侦测它** | [18:13]–[18:28] |
   | **padding** | RF 超出影像范围就**补值**；最常用**补 0**（zero padding），也可以补全图平均值、或复制边缘的值。⇒ 让图片**每一寸土地**都被某个 RF 覆盖 | [18:43]–[20:20] |

     ![[P31_06_简化一典型设定.png]]
     > 图注：投影片把上表五项**一次标在同一张图上** —— 红线框 = 一个 RF（`kernel size (e.g., 3 x 3)`）；`all channels` 指这个框**贯穿三层**；`stride = 2` 是往右挪两格得到下一个 RF；`overlap` 标出相邻两个 RF 的重叠区；`padding` 标在最右边（那里的 RF 已经探到影像之外，要靠补值）。

7. ⭐ **观察二 → 简化二：参数共享 → filter**（[20:26]–[26:13]）
   - **观察**：同样的 pattern（鸟嘴）会出现在图片的**不同位置**。因为 RF 盖满全图，所以每个位置都有一组 neuron 在守备，其中都有一个负责"侦测鸟嘴"的 neuron。
   - **问题**：这些侦测鸟嘴的 neuron **做的事一模一样，只是守备范围不同** ⇒ 每个范围都放一个是**重复**、参数太多。
     ![[P31_07_观察二_pattern出现在不同位置.png]]
     > 图注：上下两张鸟图各框出一块**鸟嘴**，右边两个 neuron 说同一句话「**I detect "beak" in my receptive field.**」⇒ 中间那个红箭头写的就是本集的**问题**：「**Each receptive field needs a "beak" detector?**」—— 每个 RF 都配一个"鸟嘴侦测器"，是不是重复了？
     - 老师的类比 [22:10]–[22:38]：教务处推动**大型课程** —— 每个系都需要机器学习课，那到底每个系都开一门，还是开一门大班课让所有人来修？
   - **简化**：让不同 RF 的 neuron **共享参数（parameter sharing）** [22:41]–[22:54]。
     - 共享 = 两个 neuron 的 weight **完全相同**（老师用颜色标注：上面这个的第一个 weight 叫 w₁，下面这个的第一个 weight **也是** w₁）[22:59]–[23:40]。
     - ⚠️ **共用参数 ≠ 输出一样**：因为**输入不同**（守备范围不同）—— 上面的输出是 x₁w₁ + x₂w₂ + …，下面是 x₁′w₁ + x₂′w₂ + … [23:43]–[24:28]。
       ![[P31_08_简化二_共享参数.png]]
       > 图注：投影片把两个 RF 的 neuron 并排画 —— 上下两个 neuron 的 weight 标签**都是 w₁、w₂**（共享），但输入分别是 x₁x₂… 与 x₁′x₂′…（**不同**）⇒ 于是公式是 σ(w₁x₁+w₂x₂+…) 与 σ(w₁x₁′+w₂x₂′+…)。⚠️ 页脚那句「**Two neurons with the same receptive field would not share parameters**」正是下一条的反例。
     - ⚠️ **反例（提醒）**：**守备"同一个" RF 的两个 neuron 共享参数就没意义** —— 输入一样，输出必然一样 [24:29]–[24:50]。⇒ **共享的前提是"守备范围不同"。**
   - **经典共享方式**：每个 RF 都有 64 个 neuron；**第 i 个 neuron 与所有 RF 的第 i 个 neuron 共享** ⇒ **每个 RF 都只有一组参数** [25:04]–[25:56]。这组被共享的参数就叫一个 **filter**（filter1、filter2 … filter64）[25:57]–[26:13]。
     ![[P31_09_简化二典型设定_filter.png]]
     > 图注：投影片用**颜色**表示"哪几个 neuron 共享同一组参数" —— 每个 RF 里的 **filter 1**（红）彼此共享，filter 2（黄）、filter 3（绿）、filter 4（蓝）同理，一直排到 **64**。页面上那两句就是这条规则：**Each receptive field has a set of neurons (e.g., 64 neurons)** + **Each receptive field has the neurons with the same set of parameters**。

8. ⭐⭐ **两个简化的总结：CNN 是个 model bias 更大的模型**（[26:17]–[29:07]）—— **这段是本集与第 2 讲的接口，非常关键**
   - **fully connected**：弹性**最大** —— 它可以自己决定"要看整张图"还是"只看一个范围"（只看一小块 = 把其他 weight 设成 0）。
   - **加上 RF**：**没得选了**，只能看一个小范围 ⇒ **弹性变小**。
   - **再加上参数共享**：某些 neuron 的**参数被强制一模一样**，连"各自学出不同参数"的自由都没有 ⇒ **弹性更小**。
   - ⇒ **RF + 参数共享 = convolutional layer**；用它的网络 = **CNN**。
   - ⇒ ⭐ **CNN 的 model bias 比较大**。但老师强调：**model bias 大不一定是坏事** —— 弹性高容易 overfitting；convolutional layer 是**专门为影像设计**的（RF、参数共享这两个观察都来自影像），所以**在影像上仍然做得好**。
     ![[P31_10_卷积层的收益_model_bias更大.png]]
     > 图注：这页就是"两个简化"的**总账** —— 三层同心椭圆：外 **Fully Connected Layer** ⊃ 中 **Receptive Field** ⊃ 内 **Parameter Sharing**（合起来才叫 **Convolutional Layer**）。右上的 `Jack of all trades, master of none`（样样通、样样松）配**外层**，右下的 `Larger model bias (for image)` 配**内层**；底下两条 bullet 就是那两个观察本身。
   - ⚠️ **但它用在影像之外的任务上就要很小心** [28:56]–[29:07] —— 必须检查那个任务**有没有影像的这些特性**。
   - 🔗 **接到第 2 讲**：这正是 [[第18集_机器学习任务攻略|第18集]] 说的"**CNN 是硬塞进网络架构里的、针对影像的先验知识**，它其实是 fully-connected network 的**真子集**，弹性更小，但在影像上反而做得更好"；也是 [[第23集_再探分类器与机器学习原理|第23集]] 那条"**限制模型复杂度 ↔ 理想与现实**"主线的实作版。

9. **第二个版本的故事：filter 扫过图片 = convolution**（[29:07]–[39:27]）
   - 老师明说：**"跟刚才讲的介绍方式是一模一样的，只是同一个故事用不同的版本来说明"** [29:14]–[29:40]。
   - **定义**：一个 convolutional layer 里**有一排 filter**，每个 filter 的大小 = **3×3×channel**（彩色 3 channel / 黑白 1 channel）[29:45]–[30:11]；filter 里的数值**就是 model 的 parameter**，由 gradient descent 学出来 [30:56]–[31:04]。
     ![[P31_11_第二个故事_filter就是参数.png]]
     > 图注：投影片把 `Convolution` 方框放大，里面是**一排 3×3×channel 的立方块**，标成 Filter 1、Filter 2……；旁边贴图注写明「**Each filter detects a small pattern (3×3×channel)**」。⚠️ 这些格子里的数字**就是参数**，不是人为指定的 —— 老师在 6×6 例子里先把 filter 的值给出来，只是为了让你看得懂扫描过程。
   - **运作**（老师的例子：黑白 6×6 图、filter 已知）[31:16]–[34:40]：
     1. 把 filter 放在左上角，和它盖住的 9 个数字做 **inner product**（逐对相乘再相加）→ 得到 **3**；
     2. 往右移 **stride = 1**，再算 → -1；再移、再算 …… 扫完一行换下一行，直到右下角（答案 -1）；
     3. filter1 的对角线全是 1 ⇒ **图里哪里出现"对角线三个 1"，输出就最大** ⇒ 输出里左上角、左下角的值最大 ⇒ 说明那里出现了这个 pattern；
       ![[P31_12_filter1扫图输出.png]]
       > 图注：这就是那 16 个数字的全貌 —— 左：**6×6 image**；右上：**Filter 1**（对角线三个 1、其余 −1）；右下：`stride=1` 扫完得到的 **4×4** 输出 `3, −1, −3, −1 / −3, 1, 0, −3 / −3, −3, 0, 1 / 3, −2, −2, −1`（老师口述的"3""−1""答案 −1"分别是左上角、第一个右移、右下角）。⭐ **对角线三连 1 出现在哪，输出就在哪最大**。
     4. 每个 filter 都做一遍同样的扫描（filter2 侦测"1 排成一条直线"…）。
   - ⭐ **feature map**：每个 filter 扫完都产生**一群数字**；**64 个 filter → 64 群数字**，这群数字就叫 **feature map** [33:49]–[34:17]。
     ![[P31_13_filter2与feature_map.png]]
     > 图注：换成 `Filter 2`（三列 −1,1,−1）再扫一遍 —— 页面上那句 **Do the same process for every filter** 就是"每个 filter 都要扫一次"，黑方块标出的名字就是 **Feature Map**。⚠️ 图上**橙、蓝两群数字是叠着画的**，代表两个 filter 各产出一张 map（= 两个 channel），**不是一张图**。
     - 例子里每个 filter 产生 **4×4** 个数字 ⇒ feature map 就是 **4×4×64**。
     - ⭐ **可以把 feature map 看成"另一张图片"，只是它的 channel 不是 RGB，而是 64 个** —— 每一个 channel 对应一个 filter [34:40]–[35:06]。
   - **叠第二层** [35:06]–[36:28]：第二层的 filter 也是 3×3，**但它的"厚度"必须是 64** —— 因为**输入的 channel 数是 64**（= 上一层 filter 的个数）。
     ![[P31_14_叠第二层_厚度64.png]]
     > 图注：投影片把这件事画成一条链 —— `64 filters` → 输出的 **"Image" with 64 channels** → 第二层的 **`Filter: 3 x 3 x 64`**。⚠️ 条形字幕写得很直白：「**只是这把 Filter 它们的高度是 64**」—— 他说的"高度"就是**厚度 = channel 那一维**（见 §5 第 5 条）。
     - ⚠️ 老师口述时把这个"厚度"叫成"**高度**"（[35:26]「它的高度必须设为 64…… filter 的高度就是它要处理的影像的 channel」）—— **他说的"高度"= 第三维 = channel 数**，别和 3×3 里的那个"高"混。
   - ⭐ **回答"3×3 会不会看不到大 pattern"** [36:28]–[37:36]：**不会**。第二层的 filter 虽然只有 3×3，但它在**原图上覆盖的是 5×5** —— 因为第一层输出的一个数值，本身就代表原图 3×3 的信息。
     - ⇒ **网络叠得越深，同样是 3×3 的 filter，它看的范围就越来越大** ⇒ "network 够深，你不用怕你侦测不到比较大的 pattern"。
     - ⚠️ **这是"结构"决定的，跟训练没关系**（提醒：不要把"叠深"记成"训练"）。
   - **两个版本的对上** [37:39]–[39:27]：第一个故事里"**共享的参数**"就是第二个故事里的"**filter**"；而"**把 filter 扫过一张图片**"这件事，**就是 convolution** —— 这就是 convolutional layer 名字的由来。另外：**filter 也有 bias**，只是第一个故事里没提 [38:17]–[38:34]。
     ![[P31_15_两个故事对照.png]]
     > 图注（**参数**的对上）：左边是第一个故事里的 **Receptive field**（一堆输入 → 一个 neuron），右边是第二个故事里的 **Filter（3 x 3 x channel tensor）**；被圈出来的是同一个东西，字幕原话「**就是第二个版本的故事里面的 Filter**」。⇒ **第一个故事里"被共享的那组参数" = 第二个故事里的 filter**。
     ![[P31_16_共享参数即convolution.png]]
     > 图注（**动作**的对上）：上半写 **The neurons with different receptive fields share the parameters**（= 简化二），下半写 **Each filter convolves over the input image**（= 第二个故事）；页面底部那句就是结论 —— 这个动作「**叫做 其实就是 Convolution**」。

10. **第三个常用的东西：Pooling**（[39:59]–[44:43]）
    - ⚠️ 老师**没有**把它编进"简化"里，他说的是"convolutional layer 在做影像辨识的时候，其实还有**第三个常用的东西**" [39:59]–[40:07]；它来自**第三个观察**：把一张大图 **subsampling**（比如拿掉偶数行/偶数列 → 变成 1/4 大小），**不会影响里面是什么东西**（大图是一只鸟，缩小了看还是一只鸟）[40:10]–[40:34]。
       ![[P31_17_观察三_subsampling.png]]
       > 图注：投影片只有一句话 **Subsampling the pixels will not change the object** —— 左边大图判读为 bird，右边缩小后**还是 bird**。⚠️ 这是 **pooling 的唯一起点**；注意它跟前面两个观察是**并列的第三个**，老师**没有**把它编成"简化三"（见 §4.2 判定摘要）。
    - **pooling 本身没有参数** ⇒ "**它不是一个 layer**"，比较像 activation function，是个行为固定的 operator（没有要跟 data 学的东西）[40:40]–[41:06]。
    - **max pooling**：把这些数字几个一组（例：2×2 一组），每组**选最大的那个**当代表 [41:13]–[41:38]。
       ![[P31_18_max_pooling分组.png]]
       > 图注：投影片把两张 feature map（Filter 1 橙、Filter 2 蓝）各自**切成 2×2 一组**（红框／蓝框），组与组之间**不重叠**。⚠️ 分组大小是你定的（2×2、3×3、4×4 都行）。
      - 一定要选最大吗？**不一定** —— 也有 min pooling、选平均、甚至几何平均；分组大小也随你（2×2、3×3、4×4）[41:38]–[42:03]。
      - ⚠️ 老师口述"min pooling 就是选平均"是口误：**选最小的是 min pooling、选平均的是 average pooling**。
    - **作用**：做完 convolution 得到一张多 channel 的图；做完 pooling **channel 数不变**（64 还是 64），**但图变小**（4×4 → 2×2）[42:06]–[42:41]。
       ![[P31_19_max_pooling取最大.png]]
       > 图注：每组取最大之后的**结果** —— 橙色那张留下 `3, 0, 3, 1`，蓝色那张留下 `−1, 1, 0, 3`：**4×4 → 2×2，而 channel 数不变**（仍是两张 map）。字幕里老师顺口补的那句「**我还看过选几何平均的**」就在这页。
    - **实作上常交替使用**：做几次 convolution 做一次 pooling [42:43]–[42:55]。
    - ⭐ **但 pooling 也可能伤 performance**：要侦测"非常精细"的东西时，随便 subsampling 会让结果变差 [42:55]–[43:08] ⇒ 所以近年**很多架构开始把 pooling 丢掉**，做成**全 convolution（fully convolutional）** —— 因为**算力越来越强**，而 pooling 最主要的理由本来就是**减少运算量** [43:08]–[43:44]。
    - ⭐⭐ **精确版（补充，课上没细讲；用户 2026-09-23 在此纠正过）**：
      - pooling **自身 0 参数**；
      - 但它**把进入后续层的维度变小** ⇒ **后面全连接层的参数量随之大幅下降**（例：224×224 若不做 pooling 直接拉直，就是 224×224×512 ≈ **2500 万维**进全连接层）；
      - ⚠️ **它不减少"卷积层"的参数** —— 卷积层参数量 = kernel 高×宽 × 输入 channel × 输出 channel，**跟图的尺寸无关**；不过 pooling 会减少它们的**运算量**。
      - ⇒ **所以"pooling 也会简化参数"这句话站得住**，省的是后面全连接层那一部分。

    - 一句流程：**convolution → pooling → flatten → fully connected → softmax**。
       ![[P31_20_整个CNN流程.png]]
       > 图注：这页把整集的拼图合起来 —— **右边是数据流**（cat → Convolution → Pooling → Convolution → Pooling → **Flatten** → Fully Connected Layers → **softmax** → `cat dog ……`），**左边**是把全连接那部分画成金字塔状的传统画法。条形字幕对应页脚那句「**最终得到影像辨识的结果**」。

12. ⭐ **AlphaGo：围棋为什么能套 CNN，以及"它居然没有用 pooling"**（[44:48]–[53:47]）
    - **怎么把围棋变成分类**：输入 = 棋盘上黑子白子的位置，输出 = 下一步该落子的位置 ⇒ 一个 **19×19 = 361 类**的分类问题 [45:09]–[46:40]。
    - **怎么把棋盘变成一个向量**：棋盘有 19×19 个位置 ⇒ 黑子填 **1**、白子填 **−1**、没子填 **0**（这只是其中一种表示法）[45:32]–[46:11]。
      ![[P31_21_AlphaGo_围棋看成19x19的图片.png]]
      > 图注：投影片把整条链画成一句话 —— 棋盘 → `19 x 19 matrix (image)` → `Network` → `Next move (19 x 19 positions)` / **`19 x 19 classes`**；左边列出 **Black: 1 / white: −1 / none: 0**。⭐ 底部黑框那两行「**Fully-connected network can be used** ／ **But CNN performs much better.**」就是下一条的内容。页脚字幕：「**可以看作是一個解析度 19 × 19 的圖片**」。
    - **其实用 fully connected 也能做，但 CNN 效果更好** [46:41]–[46:51]。因为**棋盘可以看成一张图片**：[46:53]–[47:22] 每个像素 = 一个可落子的位置；**AlphaGo 原始论文里，每个位置用 48 个 channel 描述**（"这个位置是不是要被叫吃""旁边有没有颜色不一样的子"……显然是**围棋高手设计**出来的）[47:33]–[48:13]。
    - **为什么影像的特性围棋也有** [48:17]–[49:50]：
      1. **重要 pattern 看小范围就知道** —— 例：白子被黑子围住的"叫吃"局面，不需要看整个棋盘 ⇒ AlphaGo **第一层的 filter 大小是 5×5**；
      2. **同样的 pattern 会出现在不同位置** —— 叫吃可以出现在左上角，也可以出现在右下角。
        ![[P31_22_AlphaGo_围棋与影像的两个共同特性.png]]
        > 图注：投影片把这两条各配一张图 —— 上半：一个"叫吃"局面被框出来，配字 `Alpha Go uses 5 x 5 for first layer`（= 第 1 条）；下半：**两张棋盘**，同一组三颗子分别出现在**左上角**与**右下角**（= 第 2 条）。页脚字幕：「**影像跟下圍棋有很多共同之處**」。
    - ⚠️ **但有一个让人想不透的地方：pooling** [49:50]–[50:41]
      - 影像做 subsampling 不影响判读；**可是棋盘拿掉一行一列，还是同一个棋局吗？** 显然不是 —— 围棋这么精细，随便拿掉一列整个局势就不一样。
      - 于是**有人就说**："CNN 里就是要有 pooling，影像都用 pooling，所以 AlphaGo 也一定有用 pooling，**去打它 pooling 这个弱点一定可以把它打爆**。"
    - ⭐⭐ **老师于是去读了论文** [50:41]–[52:57]：Nature 上的正文**只有五六页**，而且**正文里根本没讲网络架构**，细节在**附件**里。附件的描述是：

## 二、核心概念（速查）

| 概念 | 一句话 |
|---|---|
| **tensor** | 维度 > 2 的矩阵；一张彩色图 = 宽 × 高 × channel 的三维 tensor |
| **拉直（flatten）** | 把方块里的数字按固定顺序排成一排；**代价是丢掉"谁挨着谁"** |
| **receptive field（RF）** | 一个 neuron 的**守备范围**；它只看这块，不看整张图 |
| **kernel size** | RF 的**高 × 宽**（因为默认看全部 channel，所以不用讲深度） |
| **stride** | 建下一个 RF 时移动的格数；希望 RF 之间**重叠**，避免 pattern 落在交界处 |
| **padding** | RF 超出影像时**补值**（最常用补 0） |
| **parameter sharing** | 不同 RF 的 neuron **共用同一组 weight**；因输入不同所以输出**不会**相同 |
| **filter** | 被共享的那**一组**参数；一个 filter ≈ 所有 RF 上"第 i 个 neuron"的那套权重 |
| **feature map** | 一个 filter 扫过整张图得到的一群数字；**filter 个数 = feature map 的 channel 数** |
| **convolution** | "把 filter 扫过一张图片"这件事 |
| **pooling** | 把图变小（max/min/平均…）；**自身没有参数**，不是 layer |
| **fully convolutional** | 整个网络通通是 convolution、不用 pooling 的架构 |

## 三、公式与推导要点（本集的"参数账本"）

> ⚠️ 本集老师**没有写公式**，下面 3.1–3.3 是 **按字幕数字整理/补充的**，用于把数字对上账。

### 3.1 两个简化各贡献多少（老师举的例子：6×6 黑白图、3×3 filter、stride 1、64 个 filter）

先只看 **weight 个数**、不算 bias：

| 做法 | 算式 | weight 数 |
|---|---|---|
| **FC**（产生同样 4×4×64 = 1024 个输出，每个 neuron 连全部 36 个输入） | 1024 × 36 | **36864** |
| **只用 RF**（每个 neuron 只看 3×3 = 9 个输入，参数还是各有一套） | 1024 × 9 | **9216** |
| **RF + 参数共享**（= 64 个 filter） | 64 × 9 | **576** |

- 36864 ÷ 9216 = **4** ⇒ **receptive field 的贡献**（每个 neuron 从"看全图 36 个"变成"看 9 个"）
- 9216 ÷ 576 = **16** ⇒ **参数共享的贡献**（16 个 RF 共用同一组参数）
- ⇒ ⭐ **两个简化是把"参数爆炸"拆成两半各自解决的**：RF 砍"**每个 neuron 看多少**"，共享砍"**要几套**"。
- ⇒ **参数共享的压缩比 = 同一层里 RF 的个数**。

### 3.2 一层里到底有多少个 neuron（摊平了数）

同一个例子：

- RF 的个数 = **4×4 = 16**（= 输出的位置数）
- 每个 RF 的 neuron 数 = **64**（= filter 个数 = 输出 channel 数）
- ⇒ neuron 总数 = 16 × 64 = **1024**（正好等于 feature map 4×4×64 摊平后的数值个数）
- ⇒ **但这 1024 个 neuron 只用了 64 组参数**

### 3.3 三个"数字怎么来的"

| 问题 | 答案 |
|---|---|
| 输出为什么从 6×6 变 4×4？ | **6 − 3 + 1 = 4**（图 6×6、filter 3×3、stride 1） |
| 为什么是 64 组数字？ | **filter 的个数 = feature map 的 channel 数** |
| 第二层 filter 的**厚度**为什么 = 64？ | 因为 **filter 要盖住输入的全部 channel**：第一层输入黑白 → 厚度 1；第二层输入是 64 channel 的 feature map → **厚度 64** |
| 4×4 怎么变 2×2？ | pooling 把 2×2 一组挑一个最大 ⇒ 边长砍半，**channel 数不变** |
| 第二层的 3×3 为什么能看到原图 5×5？ | 第一层一个数值 = 原图 3×3 的信息；第二层再取 3×3 ⇒ 3 + 2 = **5**（每多叠一层 3×3、stride 1，边长 **+2**） |

### 3.4 ⭐ 一层卷积里，"你只能填三个空、其中一个不能填"

| # | 要填什么 | 谁决定 |
|---|---|---|
| 1 | **kernel 高 × 宽** | **你填** |
| 2 | **filter 个数**（= 本层输出的 channel 数） | **你填** |
| 3 | **filter 的厚度**（第三维） | ⛔ **不能填** —— 自动 = 输入 channel 数 = **上一层 filter 的个数** |

**顺着往下传的链条**：
> 输入 channel = C ⇒ 本层 filter 厚度 = C；本层选 K 个 filter ⇒ 输出 K 个 channel ⇒ 下一层 filter 的厚度 = K ……
> ⇒ **每一层只有"个数"是新的自由度；"厚度"永远被上一层锁死。**

⭐ **代码里的样子**（官方 2021 HW3 模板实测，补充）：

```
nn.Conv2d(3,   64, 3, 1, 1)   # 输入 3 channel → 64 个 filter，kernel 3×3，stride 1，padding 1
nn.MaxPool2d(2, 2, 0)
nn.Conv2d(64, 128, 3, 1, 1)   # 输入 64      → 128 个 filter，kernel 3×3
nn.MaxPool2d(2, 2, 0)
nn.Conv2d(128, 256, 3, 1, 1)  # 输入 128     → 256 个 filter，kernel 3×3
nn.MaxPool2d(4, 4, 0)
x = x.flatten(1)              # 注释原文：feature map must be flattened before going to fully-connected layers
```

- 接口 `nn.Conv2d(in_channels, out_channels, kernel_size, stride, padding)` 里**根本没有"厚度"这一栏** —— 因为**厚度 = in_channels**（上一层 filter 的个数自动带过来），**个数 = out_channels**。
- 一行 `nn.MaxPool2d` **一个参数都没有**（模型摘要里它的参数量列就是 0）。

## 五、易错点与纠正

1. ⭐ **"拉直"不是高级操作**，只是"换个摆法"；真正的要点是它的**代价**：排队之后**空间关系（谁挨着谁）就没了** ⇒ 这才是全连接层需要那么多参数的原因。
2. ⭐ **CNN 里"切"发生在"拉直"之前**：不是"整张图拉直成 30000 维 → 再按 kernel 切一块喂给 neuron"，而是**根本不做整图拉直**，每个 neuron 只取自己那块 RF（那一小块才被拉直成 27 维）。补充：两种说法**数值上等价**，差别在于**参数量由谁承担**。
3. **病因不是"图片数字多"**，而是"**每个 neuron 都连到每一个输入维度**"。
4. **kernel size 是二维的**（高 × 宽）—— 因为默认看全部 channel，所以描述 RF 时不用讲深度。别把"3×3"和"3 个 channel"混起来。
5. ⭐ **老师口述的"高度"= filter 的第三维 = 厚度 = channel 数**，**不是** 3×3 里的那个"高"。⚠️ 这个用词极易混淆（本笔记统一改称"**厚度**"）。
6. ⭐⭐ **"两个 64"陷阱**：第二层 filter 的**厚度 64** 与**个数 64** 来历完全不同 —— 厚度 64 是**继承来的**（= 第一层 filter 的个数），个数 64 是**这一层自己选的**。数字一样、角色不同。
7. ⭐ **一层卷积里你只有两个自由度**：**kernel 高×宽** 与 **filter 个数**；**厚度不能选**（见 §3.4）。
8. **共用参数 ≠ 输出一样** —— 输入（守备范围）不同，所以输出不同。
9. ⭐ **守备"同一个" RF 的两个 neuron 共享参数没有意义**（输入一样 ⇒ 输出必然一样）⇒ 共享的前提是"守备范围不同"。
10. ⭐ **stride 不能设太大**，因为**希望 RF 重叠**；不重叠的话，pattern 正好落在两个 RF 交界处就会**没人侦测到**。
11. **不要漏掉影像的边边** —— RF 超出范围就 padding 补值；不补的话边边的 pattern 就没有 neuron 关照。
12. ⭐ **3×3 也能看到大 pattern** —— 靠的是**叠深**（第二层看 3×3 = 原图 5×5），**跟训练无关**。
13. ⭐ **pooling 自身没有参数、不是 layer**；但它**会让后续全连接层的参数量下降**（这一点 最初说错了）。它**不减少卷积层的参数**，只减少运算量。
14. **现在丢 pooling 有两个理由，不是一个**：① 算力够了 ② **pooling 本身可能伤 performance**（要侦测很精细的东西时）。
15. ⭐ **CNN 是"为影像设计的"** —— model bias 更大**不是缺点**（影像任务上反而更好），但**用到影像之外必须先检查那个任务有没有影像的那些特性**。⚠️ **AlphaGo 就是最好的例子：它有影像的两个特性（局部 pattern、pattern 会移动），但 pooling 那条不成立 ⇒ 它的架构里就没有 pooling。**
16. ⚠️ **"CNN 很强"是错觉** —— 它**不会处理缩放与旋转**，所以影像辨识才需要 data augmentation。
17. ⚠️ **别把"架构设计"当成"照抄成功案例"** —— 老师原话："网络架构的设计**存乎一心**"。
18. ⚠️ **CNN 不是"对资料做数据处理"，而是"把先验塞进模型"** —— 数据处理（resize、标准化）改的是 **x**；RF + 参数共享改的是"**模型能看什么、谁和谁共享**"，= **缩小 function set**。⇒ 代价就是老师那句：**CNN 的 model bias 更大** [28:08]。⚠️ 理解成"数据处理"会丢掉"**用在影像之外要很小心**"这半句。详见 §七。
19. ⭐ **宽度买"种类"，深度买"范围"** —— 多加 filter 只增加"能侦测多少**种** pattern"，**不会改变单个 neuron 的视野**；要让一个 neuron 看到更大的范围，**有两条路**：① **叠深**（本集讲的那条：第二层 3×3 = 原图 5×5）② **把 kernel 设大**（例：AlphaGo 第一层就用 5×5）。⇒「要认大 pattern 就**必须**叠深」**说得太强**。
20. ⭐ **"为什么 deep（高瘦）比 fat（矮胖）好"不是本集的问题** —— 本集只说"叠深 ⇒ 感受野变大"，**没有**证明"deep 比 fat 强"（那是"同样参数量下谁表达力更强"的问题）。它挂在 [[第04集_深度学习基本概念|第04集]] / [[第13集_深度学习简介|第13集]] / [[第17集_逻辑回归|第17集]] 上，**✅ 已由 [[第33集_鱼与熊掌可以兼得的机器学习|第33集]] 专门回答（2026-09-26）**（官方投影片 `whydeep (v3).pdf`；答案 = **同参数量下 deep 需要的参数指数级地少**）。⚠️ 另外 **deep 与 fat 都是 DL**，它们才是对立面。
21. ⭐ **深层网络里"资料"和"特征"没有界线** —— 第 2 层的输入已经是第 1 层造出来的 **feature map**。⇒ **每一层 conv = 一次"机器自己学的数据转换"**（接 [[第17集_逻辑回归|第17集]]），详见 §七。

## 七、跨集接口：CNN 是"数据转换"吗？（2026-09-23 用户追问）

**用户的问法**：「CNN 的架构是不是就是专门针对图像的特性做了数据处理……这是不是也是一种数据转换（见前面 17 集笔记）」

**答：骨架对，但"转换"要拆成四层看 —— 它们作用的对象不一样。**

| 层 | 被改的是谁 | 谁在改 | 出处 |
|---|---|---|---|
| **① 数据预处理** | **x**（资料本身） | **人**（写死） | resize、标准化 |
| **② 手工 feature transformation** | **x → φ(x)** | **人**（很 heuristic，"那就不是人工智慧了"） | [[第17集_逻辑回归|第17集]] 的 XOR 例子 |
| **③ 机器自己学的 transformation** | **每一层 hidden 的输出** | **机器**（学参数） | [[第17集_逻辑回归|第17集]] 的结论：cascade 多个 logistic regression ⇒ **neuron / neural network** |
| **④ CNN 的架构先验（RF + 参数共享）** | ⚠️ **不是资料，是模型** | **人**（设计架构） | 本集 [26:17]–[29:07] |

⭐ **所以两句话都要说，少一句就偏了：**

1. **RF / 参数共享 ≠ 数据转换** —— 它们**不动资料**，改的是"**哪个 neuron 能看资料的哪一块、谁和谁共享参数**"，效果是 **缩小 function set、把 model bias 加大**（[28:08]–[28:14]）。⚠️ 把它理解成"数据处理"，就会丢掉本集最重要的那句：「**model bias 大不一定是坏事……但用在影像之外就要很小心**」。
2. ⭐ **但"叠深"确实是数据转换，而且是机器自己学的那种** —— 每个 filter 扫完整张图就产出**一张新的"图片"（feature map）**，下一层把这张新图当输入 ⇒ **第 1 层之后，"资料"就已经是上一层造出来的特征了**。⇒ 用 [[第13集_深度学习简介|第13集]] 的话说：**深层网络里"资料"和"特征"没有界线**。

⭐ **一句话打通 P17 ↔ P31**：

> **P17 回答"为什么要多层"**（因为手工 feature transformation 太 heuristic ⇒ 要让机器自己学）；**P31 回答"多层里每一层长什么样、该怎么设计"**（一层 = 一堆 filter 扫一遍 = **一次转换**；叠深 = **一串转换**，而且每层的"视野"逐步变大）。
> 两边的差别只在两点：**P17 的转换是对整个 x 做的，P31 的转换是在 RF 划定的局部上做的、而且所有位置共用同一套 filter。**

### 7.1 ⭐ "逐层变换"在 CNN 里第一次有了可指认的形态（用户 2026-09-23 的补充）

> 用户原话：「传统 CNN（针对影像处理而设计架构）在处理图像时，**将第 17 集中讲到的"将两个点分开"这样的比较抽象的任务，换成了处理图像这个更常见的场景**……具体体现在比如**一层一层感受野越来越大**，将复杂的图像 pattern 用 DL 的方式来处理，**更明显**」

- **P17 的困境**：XOR 四点一条直线分不开 ⇒ 必须做 feature transformation ⇒ 人做太 heuristic ⇒ **让机器自己学**（cascade 多个 logistic regression）⇒ 得到"多层"。⚠️ **但那时"变换"是抽象的** —— 没人说得清 hidden layer 究竟把 x 变成了什么。
- ⭐ **P31 把它变具象了**：每一层的输出不是抽象的中间值，而是**一张实实在在的图（feature map）** —— 而且"**叠深 ⇒ 感受野变大**"给"变换"配了一个**几何刻度**：浅层看小范围，深层看大范围。
- ⇒ ⭐ **两种说法其实是同一件事**：P17 的「一层 = 一次特征变换」 ⇔ P31 的「一层 = 一堆 filter 扫一遍，产出一张新图片，而且视野比上一层大一圈」。
- ⚠️ **诚实边界**：**"浅层学简单 pattern、深层学复杂 pattern"这句老师本集并没有说** —— 他给的只是**机制**（3×3 叠深 ⇒ 第二层看 5×5）；"边缘 → 部件 → 物体"这个语义结论是后来靠特征可视化得到的（补充，属学界共识，不是本集内容）。

### 7.2 ⭐ "fat 就用大 kernel" —— 方向对，但要把两个旋钮分开（用户 2026-09-23）

> 用户原话：「相对 fat 一些的模型我想大概会采用更大面积的 kernal」

- ✅ **直觉对**：**不叠深**的模型要拿到同样大的视野，**只能把 kernel 设大**（或用 pooling、dilated convolution 这类等效手段）。
- 🔧 **但 "fat" 的原义是"层少、每层宽"** —— 而 CNN 里有**两个独立的旋钮**：

| 旋钮 | 转动它买到什么 | 会不会改变视野 |
|---|---|---|
| **filter 个数**（= 宽度） | 能侦测**多少种** pattern | ❌ **不会** |
| **kernel 高×宽**（或叠深） | 能看**多大范围**的 pattern | ✅ 会 |

⇒ 准确的说法是「**不叠深的模型要靠大 kernel 补视野**」，**不是**"靠更多 filter"。

- ⭐ **把几条路排成一条轴**（整理，很好用）：

| 设计 | 视野 | 参数量（老师那个 6×6 黑白例子 / 同等输出） |
|---|---|---|
| **FC**（等价于 kernel = 整张图） | 整张图 | **最多**（另一例：3×10⁷） |
| **只做 RF**（3×3，但每个位置各有一套参数） | 3×3 | 9216 |
| **CNN**（3×3 + 参数共享） | 3×3，**叠深后变大** | **576** |
| **一层大 kernel**（如 11×11） | 11×11 一步到位 | 介于两者之间，但**比"叠深"贵** |

- **补充：大 kernel 这条路走得通，但更贵**（本集没讲）：
  - **参数账**：两个 3×3 叠起来 = 一个 5×5 的视野，参数 **18 vs 25**；三个 3×3 = 一个 7×7，参数 **27 vs 49**（VGG 的著名结论）。
  - **更要紧的差别**：大 kernel 学的是"**一整个大模板**"；小 kernel 叠深学的是"**小零件拼成大零件**" —— 后者才是 **P33 要讲的"模块化 / 呼叫同样的 sub function"** 在 CNN 里的样子（同一个 3×3 侦测器到处复用，拼出各种大 pattern）。
  - **现实印证**：主流架构（VGG / ResNet）几乎全是 3×3 叠深，**大 kernel 基本只出现在第一层**（AlphaGo 第一层用 5×5 也是这个位置）。

⚠️ **顺带一个术语提醒**：用户原话里的"**DL vs fat learning**"不是一组对立 —— 对立的是 **deep（高瘦）vs fat（矮胖）**，**两者都是 DL**。这个问题本身属于 **P33**（见 §六 留给后续第 7 条）。
