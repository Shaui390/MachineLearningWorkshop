## 一、本集讲了什么（大纲）

1. **通用作业格式**（[00:19–02:40]）：之后几乎所有作业"看起来都大同小异"——训练资料是 **(x, y) 的 pair**，测试资料**只有 x**。逐个点名：HW2 语音辨识、HW3 影像辨识、HW4 语者辨识、HW5 机器翻译……本期共 **11 个作业**。
2. **三步骤复习 + 现状**（[02:40–04:19]）：`f_θ(x)`（θ = 模型里所有未知参数）→ `L(θ)` → 解 optimization 得 **θ\*** → 用在测试资料上 → **直接跑助教给的 sample code**。
3. **问题来了**（[04:19–04:45]）：**"如果你觉得结果不满意，应该怎么办？"** → 这就是本集的标题：**破关攻略**（老师原话："这个就跟魔关羽一样"）。
4. **攻略第 1 步：先看 training data 的 loss**（[05:13–16:30]）——大还是小，决定你往左走还是往右走。
5. **第 2 步：训练 loss 小、测试 loss 大**（[16:30–18:48]）→ 才是 overfitting（或 mismatch）。
6. **overfitting 的解法**（[18:48–30:16]）：加资料 → augmentation → **限制模型**（五招）→ ⚠️ 但**别限制过头**（会回到 model bias）。
7. **怎么挑模型**（[30:16–33:00]）：Bias-Complexity Trade-off。
8. **⚠️ 别用 public testing set 挑模型**（[33:00–40:45]）：一兆个"废模型"实验 + 为什么必须切 public/private。
9. **正确做法**（[40:45–46:28]）：从 **training set** 切出 **validation set** 来选模型；怕分得不好就用 **N-fold cross validation**。
10. **实战战报 + mismatch**（[46:31–51:25]）：2/26 观看人数四个模型**全惨** → 引出本集最后一个病名 **mismatch**（不是你的模型不好，是**资料的分布变了**）。

## 二、核心概念

### 1. 攻略的入口：`loss on training data` 大不大

| 你的观察 | 病灶 | 处方 | 字幕位置 |
|---|---|---|---|
| **training loss 大** | **model bias**（弹性不够）或 **optimization**（优化不给力） | 前者 → `make your model complex`；后者 → **下一节课** | [05:13–16:30] |
| **training loss 小、testing loss 大** | **overfitting** 或 **mismatch** | 前者 → 见第 5 节；后者 → **HW11 才讲** | [16:30–18:48] |
| 两边都小 | 🙂 收工 | — | [16:11–16:30] |

> ⭐ **这张表就是本集的全部价值**。它把"训练不顺"从**一种模糊的焦虑**变成了**四个可以分别验证的病名**。

### 2. Model bias vs Optimization：怎么分辨（本集最实用的一段）

**Model bias**（[05:36–07:50]）：你的 function set 里**根本没有**一个 loss 够低的 function——就是你**弹性不够**。处方：**增加弹性**（加更多 feature；老师复习了上周的例子：从"只看前一天"改成"看前 56 天"，再用 deep learning）。

**Optimization**（[08:09–09:54]）：function set 里**明明有**好的 function，你的梯度下降**没找到**。老师的比方（[09:17–09:54]）：

> **model bias = 大海里根本没有针；optimization = 海里有针，你捞不到。**

**怎么分辨？** 看一个经典反例（[10:16–13:33]）——**ResNet 的 20 层 vs 56 层**：

![[P18_03_ModelBias_vs_Optimization_ResNet.png]]

- 左图（**Testing Data**）：56 层（红）比 20 层（黄）**更差** → 当年很多人（[11:24]）看到这张图就说"**这代表 overfitting**"。
- ⚠️ **但那不是 overfitting**。理由（[12:36–13:26]）：
  > **56 层的网络"没有道理"做不到 20 层能做的事** —— 只要后 36 层学成 identity（恒等映射），56 层就退化回 20 层。既然 20 层都能把 training loss 压到那么低，56 层**至少**也该做到。
- 右图（**Training Data**）：56 层在**训练资料上就更差** → 说明**不是**"训练好、泛化差"（那才叫 overfitting），而是**压根没训好** = **optimization 不给力**。

**实用判据**（[13:59–14:40]）：**先训一个浅模型，再训深的**。如果深的在 training set 上还不如浅的 → **铁证是 optimization 问题**（而不是 overfitting、也不是 model bias）。

### 3. Overfitting 是什么

- 判据（[16:30–17:19]）：**training loss 小 + testing loss 大**。老师吐槽："我发现十个同学有九个半都以为自己的问题是 overfitting"。
- 极端例子（[17:32–19:00]）⭐ 本集的道具：一个**"一无是处的 function"**——
  > 训练资料里出现过的 x，就背出它的 ŷ；**没见过的 x，就随便输出（random）**。
  它在 training data 上 loss 可以是 0，在 testing data 上纯属乱猜。
- 为什么会发生（[19:05–20:56]）：真实分布（虚线）不可观测，你只有**有限的**采样点；模型弹性一大，它就能穿过**所有**蓝点（连噪声一起）、却偏离真实曲线。（老师说背后的数学原理下下周讲。）

### 4. 模型复杂度 vs loss（Bias-Complexity Trade-off）

![[P18_07_BiasComplexity_Tradeoff曲线.png]]

- **training loss**：模型越复杂（feature 更多、参数更多）→ **单调下降**（[29:48]）。
- **testing loss**：**先降后升**（[30:01–30:12]）——升的那一段就是 overfitting 开始出现。
- 所以目标是**中庸**（[30:32–30:45]）：「不是太复杂的、也不是太简单的，刚刚好」。

### 5. Overfitting 的解法（四种 + 五招限制）

#### ① 增加训练资料（最有效，但作业里不能用）

![[P18_04_Overfitting_加资料与augmentation.png]]

- [21:11–21:44]：**最简单、往往最有效**的一招。蓝点变多以后，即使模型弹性很大，**也会被资料"限制住"**，形状自然贴近背后那条真实曲线。
- ⚠️ **但作业里禁止用**（[21:44–22:08]）：老师原话是「在作业里面你**不能够**使用这一招，因为我们并不希望大家浪费时间来收集资料……**这不是机器学习技术最核心的部分**」→ 投影片红字 **more training data (cannot do it in HWs)**。
  - 🔧 **口径修正**：这是**作业的设定**（怕你把时间花在爬数据上），**不是"现实中收集不到资料"**。

#### ② Data augmentation（自己创造资料）

- [22:10–23:21]：**你能不能自己创造资料？** 影像可以：**左右翻转、放大缩小**（同一张猫，位置镜射之后仍然是猫）。
- ⚠️ **但要针对问题设计**：投影片右下那张**上下翻转的猫被打了红叉**——因为对"辨识猫"这个任务来说，**倒过来的猫现实中不存在**，你造出来的资料反而在教模型错的东西（[23:10–23:21]）。
- 判断 augmentation 好不好用，**取决于你对自己问题的理解**（[23:49–24:29]）：老师说他一眼就知道观看人数预测"应该长得像二次曲线"，因为那是**人为设计的问题**，所以知道什么样的弹性刚刚好。

#### ③ 限制模型：让假设空间变窄（"根据你的理解"）

![[P18_05_Overfitting_限制模型_五招.png]]

把 model 从"什么曲线都能做"限制成 **`y = a + bx + cx²`**（老师自己举例时说的是"**我们的 model 一定是一条二次曲线**"）——一旦这么规定，**它就只能在这条二次曲线的家族里挑**，弹性立刻变小。

**投影片给的通用五招清单**（[27:11–27:53]）：

| 招 | 意思 | 备注 |
|---|---|---|
| **Less parameters / sharing parameters** | 参数变少，或**让参数共用** | 共用参数的典型 = **CNN**（影像） |
| **Less features** | 喂进去的特征变少 | |
| **Early stopping** | 训练早点停 | 之后课程细讲；**作业一 code 里助教已经写好** |
| **Regularization** | 加惩罚项（L2 等） | 之后课程细讲；**作业一 code 里留了空格给你填** |
| **Dropout** | 训练时随机关掉一部分神经元 | deep learning 里常用来限制模型；之后课程细讲 |

⭐ **CNN 的位置讲得最清楚**（[25:33–26:53]）：**CNN 是"硬塞进网络架构里的、针对影像的先验知识"**——它其实是 fully-connected network 的**真子集**，弹性更小，但在影像上**反而做得更好**。（这段话是 P31 起 CNN 那讲的伏笔。）

#### ④ ⚠️ 别限制过头 → 又回到 model bias

![[P18_06_限制过头_回到model_bias.png]]

- [27:56–28:34]：如果硬性规定 **`y = a + bx`（只能是一条直线）**，而真实资料是弯的 → **没有任何一条直线能穿过那三个点**。
- [28:38–28:57]：这时结果不好——**"这个是 overfitting 吗？这个不是 overfitting，因为你又回到了 model bias 的问题。"**
- ⚠️ **这就是本集最容易记错的一处**：**结果不好 ≠ 一定过拟合**；也可能是**你把模型限制得太死**。

> **老师这里自己承认了一个概念缺口**（[29:01–29:31]）："复杂"和"弹性"这两个词，**本集只给直观叙述**（参数多、能包含的 function 多），**严格定义在之后的课程**。

### 6. ⚠️ 不要用 public testing set 挑模型

![[P18_08_用public选模型的坑_一兆模型.png]]

**直觉做法**（[31:00–31:39]）：把三个复杂度不同的模型都跑出来、都上传 → 看 **public leaderboard** 谁分高就选谁。**老师：并不建议你这么做。**

**为什么？看极端例子**（[31:43–33:50]）：

- 假设有 **1 到 1 兆** 个模型，每个都是那个"**一无是处 function**"：训练集里见过的 x 背答案，没见过的 x **随机输出**。
- 你把这一兆个结果**全上传**，得到一兆个 public 分数 → **总有一个**（老师举例：编号 **56789**）**碰巧**在 public set 上分数很好。
- 你很高兴地选了它 —— **因为它是随机的，它在 private set 上仍然是随机的**（投影片原文：`Random on private testing set`）。
- 结果（[33:50–34:45]）：**public 上排前十，deadline 一结束掉到 300 名外**（"每年都会有这样的状况发生"）。

**那为什么一定要切 public / private？**（[35:07–36:26]）

> 因为如果**所有**资料都是 public，你回去写个程序**不断随机上传**，迟早random 出一个高分——**那这个作业就结束了，显然没有意义**。

⭐ **由此推及一个更大的道理**（[36:14–38:42]）：**benchmark corpus**（如语音辨识的 LibriSpeech、Switchboard）的测试集是**公开**的，于是"就算是个很废的模型，只要做得够多，也能在 public set 上得到好结果"→ 这解释了**为什么机器在某些 benchmark 上能"超越人类"**（[37:16] 2016 年 Microsoft 与 IBM 都宣称在语音辨识上超越专业听打员）——**但那不代表它在日常生活中真的超越了人类**（你今天用手机语音辨识就知道）。

**老师的正解**（[43:40–44:03]）：

> **用 validation loss 最小的那个直接挑，不要去看 public testing set 的结果。**

（[43:22–43:29] 附带一句现实的安慰：public 榜上排前几名的，往往最后**很容易惨掉**——所以看到"我其实只是个旁听"这种名字，**不要理他**。）

### 7. 正确做法：从 **training set** 切出 validation set

![[P18_09_CrossValidation_切法.png]]

- [40:52–41:24]：**把 training 的资料分成两半**，一部分照常训练，另一部分是 **validation set**（助教代码里默认切 **10%**）→ **在 validation set 上衡量分数、用它来挑 model**。
- ⚠️⚠️ **最容易说反的一句话**：validation set **是从 training set 分出来的，不是从 testing set 分出来的**。testing set（public + private）**从头到尾都只有评估作用**，不参与任何选择。
- 投影片用并排图对比了**错的做法**与**对的做法**：
  - 右边（**Not recommend**）：用 public testing data 的结果挑模型 → "**You are making public set better than private set**"（你在让 public 变好、private 变差）。
  - 左边：Training Set 内切出 Validation → 用 **validation 分数**挑（Model 1/2/3 → 0.9 / 0.7 / **0.5 → Pick this one!**）。

### 8. 怕验证集切得不好？→ N-fold Cross Validation

![[P18_10_Nfold_CV_平均选模型.png]]

- 担忧（[44:48–45:03]）：万一我**分到一组很奇怪的 validation set**，结果不就差了？
- 做法（[45:03–46:28]）：把 training set **切成 N 等份**（例子里 N=3），轮流拿其中一份当 validation、其余当 training，**每轮都跑一遍所有候选模型**，最后**把每个模型在 N 轮的结果平均**：
  - Model 1：0.2 / 0.4 / 0.3 → **Avg = 0.3** ⭐ 最好
  - Model 2：Avg = 0.5 ｜ Model 3：Avg = 0.4
- ⭐ **最后一步**（[46:18–46:28]）：选定 model 1 之后，**用它（的结构）在"全部" training set 上重新训练一次**，训练出来的模型才拿去碰 testing set。

### 9. mismatch：训练/测试分布不一样（本集收尾，⭐ 最后 2 分半）

**现场战报**（[46:49–48:50]）：

- 上周大家投票选了 **3 层网络**去预测 2/26 的观看人数，老师说"我们就没有再调参数了，大家决定用三层的，就直接用上去"。
- 结果（[47:40–48:11]）：**非常惨，差距 2.58k**；他还顺手跑了 1/2/4 层——**四个模型全惨**（2/3 层误差 2.多k，1/4 层约 1.8k）。
- 真相：**2/26 是当年观看人数最高的一天**（老师自嘲"感谢大家，为了让这个模型不准，上周我花了很多力气去点这个 video"）。
- ⚠️ **但"不能怪模型"**（[48:26–48:41]）：根据**过去的资料**，礼拜五晚上大家都出去玩、**观看人数最少**——模型判断它是个低点，完全合理。**是这一天反常**。

**定名与要点**：

| 要点 | 内容 | 位置 |
|---|---|---|
| 定义 | 训练资料与测试资料的**分布不一样** | [48:42–48:50] |
| 与 overfitting 的关系 | [48:52]「那也有人会说 **mismatch 也算是一种 overfitting**」——但**机制不同**（不是模型太复杂，是资料本身变了） | [48:50–49:01] |
| ⭐ 关键 | **mismatch 用"收集更多资料"是解决不了的**（因为多收的资料仍然来自**同一个错分布**） | [49:08–49:11] |
| 作业里会不会遇到 | **多数作业不会**（切分时已避开）；**只有 HW11 是针对 mismatch 设计的**（[50:34] 它的训练资料看起来很"正常"，但测试资料长得很怪） | [50:21–50:49] |
| 怎么知道自己是 mismatch | ⚠️ **没有自动判据**：要靠你对**训练资料和测试资料的"产生方式"的理解** | [50:55–51:14] |

## 三、公式与要点速查

| 概念 | 一句话 |
|---|---|
| 三步骤 | `f_θ(x)` → `L(θ)` → `argmin L → θ*`（θ = 模型里所有未知参数）[03:04–03:40] |
| 四种病灶 | **model bias**（弹性不够）／**optimization**（没找到）／**overfitting**（训练好、泛化差）／**mismatch**（分布变了） |
| 分辨 model bias vs optimization | **先训浅模型**；深的在 training set 上更差 → optimization [14:18–14:40] |
| 分辨 overfitting vs mismatch | 看**测试资料的来源**是否与训练资料同一分布；mismatch **加资料没用** [49:08] |
| Bias-Complexity | training loss 单调降；**testing loss 先降后升** → 取最低点 [30:01] |
| 选模型 | 用 **validation set**（从 **training** 切，默认 10%）→ 切的组不好就用 **N-fold CV**（平均） |
| 选完以后 | 用**全部** training set 重训一次再上测试集 [46:18] |

| 2 | 为什么用 public 挑模型，真实水平会比榜上差？ | "仅用 public 表现训练效果的模型，可能只是在 function set 中**随机出来的结果刚好过拟合了 public 集**，不代表真的训练得很好" | ⚠️ **方向对、机制补一格**：真正的一般机制是**"选择"本身在过拟合**——你在一大堆候选里挑 public 最高的那个，等于拿 public 当训练资料用（`P18_09` 的红字：you are making public set better than private set）。**"随机"只属于老师那个极端例子**（一兆个"背答案+乱猜"的模型，总有一个**碰巧**） |
| 3 | 训练 loss 小/测试 loss 大 与 训练 loss 本身就大，能开同一张药方吗？ | "不能。前者是**过拟合/mismatch**，后者是 **model bias / 优化方法不对**" | ✅ **完全正确**。这张四岔路就是你带走的东西 |
| 4 | 五招里哪一招是"减少参数**有效数量**"而不是"减少参数**个数**"？ | "**共用参数（CNN）**，这就不是一个全连接神经网络了；但图中用了一个 v 图的方法来表示，意思是说产生的 function set 是这样的关系" | ✅ **答对了**（= `sharing parameters`；图里那个小 CNN 圆嵌在 Fully-connected 大圆里，正是"**CNN 的假设空间是 FCN 的真子集**"）。⚠️ 表述小修：投影片画的**不是 V 形关系图**，而是**两个同心椭圆**（大 = Fully-connected，小 = CNN）——它表达的是**包含关系**，不是 V 字 |
| 5 | 为什么用 validation 挑完还要用全部资料重训一遍？ | "对这样的模型来说训练资料肯定越多越好；validation 本身就是从初始训练集里分出来的，把它放进去重训能提高在测试集上的表现" | ⚠️ **结论对、理由漏了关键一层**：⚠️ **不能让"用来挑选的资料"同时参与训练**——如果 Model 1 是同一次训练里跑出来的，它的 validation 分数就**不再是对它泛化能力的公正估计**（因为它是**被选中**的那个：在一堆模型里选 validation 最低的，等于让 validation 也承担了"训练/选择"的角色 → 分数偏乐观）。所以正确的顺序是：**① 用 validation 挑出赢家 → ② 把 validation 并回训练集、用全部资料从头重训那个赢家 → ③ 这才去碰 testing set**。你答的"资料越多越好"是对的**附加好处**，但不是**必须重训**的理由 |

## 五、易错点与纠正

1. ⚠️⚠️ **"结果不好"≠"过拟合"**。本集出现了**三种**会让结果不好的原因：model bias（弹性不够）、optimization（没训好）、限制过头（**又回到 model bias**）。老师原话 [28:44]："这个是 overfitting 吗？**这个不是 overfitting**。"
2. ⚠️ **validation set 是从 training set 切的**，不是从 testing set 切的 [40:57]。testing set 全程**只评估、不选择**。
3. ⚠️ **public 分数高 ≠ 模型好**。用 public 挑模型 = 拿 public 当训练资料，会让 **public 变好、private 变差**（`P18_09` 红字）。
4. ⚠️ **别用测试集/榜单调参**（P15 就埋下的坑，本集正式给了答案）：任何"看了分数就回去改"的循环，都在污染评估集；这也是作业限制上传次数的原因 [40:32]。
5. ⚠️ **augmentation 不是随便造资料**：**要符合你对问题的理解**（上下翻转的猫被打红叉）。
6. ⚠️ **"减少参数"与"减少参数的有效数量"是两件事**：CNN 靠**共用参数/局部连接**把有效假设空间压小，参数个数未必少。
7. ⚠️ **mismatch 加资料没用** [49:08]；而且它**没有自动判据**，只能靠你对"资料是怎么产生的"的理解 [50:55]。
8. ⚠️ **"复杂/弹性"本集没有严格定义**（老师自己承认 [29:01]）——本集只给"参数多 = 能包含的 function 多"这种直观说法，别当成定义背。
9. ⚠️ **这份攻略是"通用前期攻略"**（[46:31] 老师说"它可以带你打赢**前期所有**的部分"），不是万能药——第四种病 mismatch 的解法被推到了 HW11。
